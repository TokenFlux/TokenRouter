# Register a plugin

1. Publish a `v<SemVer>` release with the matching `plugin.json`, `checksums.txt`, and
   platform archives generated by `trplugin pack`. Run `trplugin validate` first.
2. Add `publishers/<prefix>.yaml` with `id`, `name`, `url`, and the GitHub accounts or
   organizations authorized to maintain that prefix. A new publisher submission
   includes at least one plugin and requires a maintainer's `publisher-approved` label.
3. Add `plugins/<prefix>/<name>.yaml` with the full `id`, public GitHub `repository`,
   and `categories`. Optional fields are `minVersion`, `delisted`, and `yanked`.
4. Explain permission use in the pull request template. Existing publisher changes
   are checked against the base branch's ownership list, including edits to the
   publisher file itself. Proposed scripts and plugin binaries do not run in validation.
5. A maintainer reviews the public source and release correspondence before merging.

Categories are `engagement`, `tools`, `analytics`, `content`, `integration`, and `other`.
Keep registrations when withdrawing a plugin: set `delisted`, or append a version and
reason to `yanked`. Delete-and-recreate submissions cannot bypass publisher ownership.
