# Project Doc

把文档库作为代码库的同步组成部分。只记录需要跨越局部代码才能理解的持久工程知识，并让目录、正文、代码锚点与当前实现保持一致。

## 开始任务

1. 确认当前请求是只读任务还是允许修改文件的实施任务。只读任务只报告文档漂移，不写入修复。
2. 确定仓库根目录，并遵守仓库中已有的 Agent 指令。
3. 查找项目指令中声明的文档根和根 `index.md`。没有声明时，优先使用明确的现有文档根，否则使用 `docs/`。
4. 如果文档库已建立，在分析业务代码前按下方“读取与上下文复用”规则读取或复用根 `index.md`；再按其中的“读取时机”进入相关分类 `index.md`。
5. 如果遇到 `@project-doc`，在理解、审查或修改锚点所属语义单元前，按同一规则读取或复用目标章节。
6. 如果存在 `<doc_root>/.project_doc_bootstrap.md`，读取它并按记录的下一步恢复建库，不重新规划已完成工作。

项目指令已经声明 Project Doc 门禁、但根目录与建库备忘录都不存在时，停止仓库任务并报告接入不完整。除非用户明确要求首次建库，否则不要擅自创建整套文档库。

## 读取与上下文复用

- 当前会话首次在某个仓库执行任务时完整读取根 `index.md`；后续任务、子任务、文件修改和任务收尾均可复用已读内容，不以这些步骤本身作为重读触发条件。技能说明、引用协议、分类目录和正文同样适用。
- 复用的前提是当前上下文或压缩摘要仍保留所需内容：路由所需的分类、路径和读取时机，以及当前操作涉及的约束。只记得“已读过”或仅有文件名不够；内容遗失时只补读缺失的索引或章节，根路由整体遗失时再完整读取根索引。上下文压缩本身不要求重读。
- 已知相关文件被外部修改、仓库或文档根切换、路由与实际文件冲突，或用户要求刷新时，重新获取受影响的内容。本轮自己完成且仍记得的修改可以直接更新上下文，无须为确认修改而重读全文；不要在每次操作前轮询时间戳或哈希。
- 任务扩展到未读领域时，沿已知路由补读对应分类和必要章节，不自动重读根索引或其他已读分类。
- 复用只减少重复读取，不免除文档影响判断、同步维护和必要验证；不为此创建持久化缓存、已读清单或无影响声明。

## 选择工作模式

- **首次建库或恢复建库**：读取 [references/bootstrap_workflow.md](references/bootstrap_workflow.md)、[references/library_protocol.md](references/library_protocol.md) 和 [references/anchor_protocol.md](references/anchor_protocol.md)，再使用 `assets/` 中的模板。
- **随代码维护**：读取 [references/library_protocol.md](references/library_protocol.md)；遇到、添加、移动或删除锚点时再读取 [references/anchor_protocol.md](references/anchor_protocol.md)。
- **一致性审计**：读取文档库协议与锚点协议，核对目录、正文、代码和引用；是否修复取决于用户是否授权修改。
- **按文档回答问题**：只读取或复用根目录、命中的分类目录和必要章节，不展开无关文档。

## 执行同步维护

1. 从任务涉及的代码路径、符号、配置、测试和锚点确定可能受影响的文档。
2. 按“读取与上下文复用”规则获取目标章节及其理解所必需的相邻章节，不默认读取整个文档库。
3. 结合实现、调用方、测试、配置、历史和用户目标判断真实契约。
4. 按 [references/library_protocol.md](references/library_protocol.md) 决定创建章节、创建文档、更新、移动、合并、删除或保持不变。
5. 获得修改授权时，在同一变更中维护代码、文档正文、各级 `index.md`、锚点和普通链接。
6. 使用仓库现有工具、`rg`、必要的局部读取和 Git diff 检查本次变更影响的文档结构与引用，不在收尾时默认重读各级索引或审计全库；继续运行代码变更本身要求的测试。
7. 在结果中说明修改了哪些文档；没有文档影响时，说明已完成影响判断，但不要创建持久化的无影响声明。

## 保持这些不变量

- 根 `index.md` 的首次完整读取与后续复用遵循“读取与上下文复用”；分类目录和正文始终按需获取。
- 根目录负责分类路由，分类目录负责列出该分类的每篇文档及读取时机。
- 代码锚点只指向带显式稳定 ID 的语义章节，不指向标题自动生成的 slug。
- 普通文档描述当前状态；重要历史决策使用 ADR，并通过 `superseded` 状态保留已替代决策。
- 不为局部实现细节、机械重构、生成代码、临时计划或可直接从单个符号得出的事实创建文档。
- 不因文档与代码冲突就默认修改其中一方；先核实意图，高影响歧义无法消除时再询问用户。
- 不在只读请求中修复文件，不把文档同步扩展成用户未授权的行为变更。
- 不生成项目专用校验脚本、CI 或文档影响声明，除非用户另行明确要求。

## 接入要求

首次建库时，按 [references/bootstrap_workflow.md](references/bootstrap_workflow.md) 写入项目级技能门禁。门禁必须要求 Agent 在任何仓库操作前确认当前会话能够调用 `project-doc`；不能调用时立即拒绝继续，不能把磁盘上存在同名文件当作技能已经加载。

建立或审计文档库时检查门禁是否缺失或过期。写任务中修复门禁，读任务中只报告问题。
