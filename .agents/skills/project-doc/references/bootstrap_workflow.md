## 前置条件

只有用户明确要求建立、接入、恢复或重建 Project Doc 文档库时才进入本流程。普通代码任务发现仓库没有文档库时，不要擅自启动大规模建库。

开始前：

1. 确定仓库根目录并读取已有项目指令。
2. 确认用户允许创建文档、重命名纳入的遗留文档、修复引用并更新 Agent 指令入口。
3. 识别用户指定的文档根；没有指定时按文档库协议选择现有文档根或 `docs/`。
4. 读取 [library_protocol.md](library_protocol.md) 和 [anchor_protocol.md](anchor_protocol.md)。
5. 使用 [index.md](../assets/index.md) 与 [project_doc_bootstrap.md](../assets/project_doc_bootstrap.md) 作为结构模板，按仓库主语言改写，不原样保留占位符。

## 盘点仓库

先建立证据清单，不立即撰写大段正文。至少检查：

- 根级和子目录 Agent 指令，确认适用范围与优先级。
- 包管理、构建、部署和工作区清单。
- 应用入口、模块边界、公共接口、配置、schema、迁移和测试。
- 生成目录、第三方代码、构建产物和不应文档化的临时文件。
- README、现有文档目录、源码旁文档及仓库内指向它们的链接。
- 已有 ADR、设计说明、运维手册和可能已经失真的文档。

为每份已有文档选择一种处置：

- `adopt`：内容与边界基本正确，纳入目录并补齐必要结构。
- `update`：保留文档身份，按当前代码修正。
- `merge`：有效知识并入更合适的现有或计划文档。
- `split`：一个文件混合了不同主题、受众或更新周期。
- `exclude`：不属于持久工程知识，保持在文档库之外。

纳入的文件或目录不符合小写 `snake_case` 时必须重命名。先枚举所有仓库内引用，再分批移动并修复链接，避免只改路径不改消费者。

## 设计完整目录

在填充正文前确定整个文档库框架：

1. 写出根级文档和实际需要的分类。
2. 为每个分类列出计划文档、范围、权威代码来源和读取时机。
3. 判断哪些主题扩展现有文档，哪些需要新文档，哪些属于 ADR。
4. 为需要代码提醒的章节规划语义入口和稳定 ID。
5. 建立根 `index.md` 与所有计划分类的 `index.md` 骨架。

根目录只路由分类和根级文档；分类目录列出该分类的每篇文档。计划文件尚未创建时，目录中使用代码格式路径而不是失效 Markdown 链接。

向用户展示目录结构摘要。只有领域边界、文档根、遗留文档处置或大规模重命名存在高影响歧义时才暂停询问；其他情况记录假设并继续。

## 建立备忘录

从模板创建 `<doc_root>/.project_doc_bootstrap.md`，并在任何正文批次开始前填完整：

- 文档根、仓库主语言和最后更新时间。
- 已锁定的结构决策与命名约束。
- 每篇计划文档的范围、权威来源、遗留处置和锚点目标。
- Agent 指令入口的接入状态。
- 当前阻塞项、下一项唯一动作和交接说明。
- 已执行验证及其结果。

文档状态只使用：

- `planned`：范围与来源已确定，尚未开始正文。
- `in_progress`：当前正在核实或撰写；同一时刻只保留一个。
- `verified`：正文、目录、锚点和链接均已核实。
- `blocked`：存在明确阻塞条件，并记录恢复所需信息。

每完成一篇文档、一次遗留重命名或一次门禁更新后立即刷新备忘录。主动交接或主动压缩上下文前也必须刷新。未完成建库时允许保留并提交该文件，不能为了让工作树看起来完整而提前删除。

## 安装技能门禁

创建根目录骨架和备忘录后，接入项目级门禁。检查以下根级入口：

- `AGENTS.md`
- `CLAUDE.md`
- `GEMINI.md`
- `.github/copilot-instructions.md`

更新所有已经存在的入口。一个都不存在时只创建根 `AGENTS.md`，不要顺带创建其他 Agent 专用文件。不要修改嵌套入口，除非用户明确要求文档库只适用于某个子树。

使用唯一的 `## Project Doc 门禁` 二级标题维护门禁块。门禁块从该标题开始，到下一个二级标题或文件结尾结束；不要添加仅用于标记边界的 HTML 注释。

```markdown
## Project Doc 门禁

- 执行任何仓库任务前，先确认当前 Agent 会话能够调用名为 `project-doc` 的技能。
- 如果不能调用，立即停止；不得读取业务文件、运行仓库命令、执行分析或修改文件。
- 技能不可用时，只回复：“当前环境未安装或未加载 `project-doc` 技能，按仓库规则无法继续。请安装或启用该技能，并在新会话中重试。”
- 如果能够调用，先使用 `project-doc`；当前会话首次处理本仓库任务时完整读取 `<doc_root>/index.md`，再按目录路由完成任务。
- 同一会话中已读取且仍保留足够内容的技能说明、索引和相关章节可以复用；修改文件、继续子任务或任务收尾本身不触发重新读取。内容缺失、相关文件变化或路由冲突时，按技能的“读取与上下文复用”规则补读受影响部分。
```

按仓库主语言翻译正文时，必须保持门禁语义和固定拒绝行为不变。将 `<doc_root>` 替换为实际路径。

门禁更新必须幂等：

- 没有门禁标题时追加一个完整门禁章节，并保持原有内容不变。
- 已有一个门禁标题时原位更新该章节。
- 存在多个同名门禁标题时合并为一个并报告原有漂移。
- 不把磁盘上存在技能目录当作当前会话已经加载技能。
- 不为其他 Agent 生成兼容技能；它们必须自行安装可调用的同名技能。

如果现有项目指令与门禁直接冲突，不静默覆盖冲突规则；记录证据并询问用户。

## 分批填充文档

按依赖从宽到窄推进，通常采用以下顺序：

1. 项目范围、关键术语和整体边界。
2. 架构、组件关系和跨模块流程。
3. 领域规则、状态机和不变量。
4. 接口、配置、事件和数据契约。
5. 部署、迁移、恢复、观测与安全运行。
6. 需要保留理由和取舍的 ADR。

每个批次只处理一个明确文档：

1. 把该项状态改为 `in_progress` 并记录下一步。
2. 阅读列出的权威来源及必要调用方和测试。
3. 撰写当前状态正文；不从文件名或旧文档猜测行为。
4. 为需要代码提醒的章节添加稳定 ID。
5. 在手写语义入口添加选择性 `@project-doc` 锚点。
6. 更新分类目录和相关普通链接。
7. 检查正文、链接、锚点和命名后改为 `verified`。
8. 立即更新备忘录，再开始下一项。

不要先生成所有正文再统一核实，也不要把占位文档标记为已完成。

## 恢复未完成建库

发现 `.project_doc_bootstrap.md` 时：

1. 在根 `index.md` 之后立即读取备忘录。
2. 对照当前文件树和 Git diff 验证备忘录仍然有效。
3. 检查是否存在残留的 `in_progress` 项，判断它已完成、需继续还是应回退为 `planned`。
4. 从“下一项唯一动作”继续，不重新盘点已经验证的领域。
5. 新发现会改变整体结构时更新结构决策，并同步受影响的目录条目。

不要仅凭聊天记忆恢复进度；备忘录和当前仓库状态共同构成恢复依据。

## 完成条件

只有同时满足以下条件才能结束首次建库：

- 所有计划条目均为 `verified`，没有 `in_progress` 或未解释的 `blocked`。
- 根目录和分类目录准确路由全部文档，不存在计划状态或失效链接。
- 所有纳入的文件、目录和章节 ID 符合命名规则。
- 所有 `@project-doc` 锚点都指向存在的具体章节。
- 遗留文件重命名后的旧路径和旧链接没有残留。
- Agent 指令入口各自只有一个有效门禁块。
- 文档内容已与当前代码、测试和配置交叉核实。

完成最终审计后删除 `.project_doc_bootstrap.md`，并再次确认根目录没有指向它。存在任何未完成项时保留备忘录并明确报告剩余工作。
