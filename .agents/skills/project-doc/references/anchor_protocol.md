## 语法

代码锚点使用单行、可搜索的固定标记：

```text
@project-doc docs/<path>.md#<section_id>
```

`docs/` 表示默认文档根。项目选择其他文档根时，使用从仓库根开始的实际相对路径。不要使用绝对路径、`../`、编辑器 URI、远程仓库 URL 或只依赖当前文件位置的相对路径。

每个锚点必须满足：

- 标记严格写为小写 `@project-doc`。
- 文档路径从仓库根开始，并指向已纳入目录系统的 Markdown 文件。
- 路径中的文档文件和目录使用小写 `snake_case`。
- `section_id` 使用 `[a-z][a-z0-9_]*`。
- 一行只放一个目标；同一语义入口确实依赖多个章节时使用多行锚点。

目标章节在标题前放置显式 HTML ID：

```markdown
<a id="account_selection"></a>
## 账号选择
```

不要依赖 Markdown 渲染器根据标题自动生成的 slug。标题可随表达改进，稳定 ID 只有在章节语义身份改变时才更换。

## 注释形式

使用目标语言原生注释包裹锚点，不添加无关说明：

```go
// @project-doc docs/architecture/request_routing.md#account_selection
func selectAccount(...) {
```

```typescript
// @project-doc docs/interfaces/session_contract.md#refresh_rules
export async function refreshSession(...) {
```

```python
# @project-doc docs/domains/billing.md#balance_invariant
def apply_charge(...):
```

```sql
-- @project-doc docs/domains/usage.md#aggregation_boundary
CREATE TABLE usage_records (...);
```

```html
<!-- @project-doc docs/interfaces/authentication.md#login_flow -->
<LoginForm />
```

协议标记本身不是自然语言注释。需要额外解释时，使用仓库规定的注释语言，并与锚点分行。

## 放置位置

只在阅读代码时确实需要跳转到非局部知识的位置放置锚点，优先级如下：

1. 子系统或跨模块流程的手写入口。
2. 拥有核心不变量的类型、接口或状态机。
3. 对外契约的实现边界。
4. 无单一入口时最接近语义所有权的手写代码。

把锚点放在所属符号或配置块附近，不要为了显眼统一堆在文件头。一个章节可以由多个真实入口引用，但不要在所有相关文件中复制锚点。

默认不在以下位置放置：

- 生成代码、vendored 代码、压缩文件和锁文件。
- 不能包含注释的 JSON 等格式。
- 只记录历史步骤而不是当前语义所有权的迁移文件。
- 与生产语义重复的普通测试。

无法直接注释目标文件时，把锚点放在生成源、schema、加载器、验证器或最近的手写语义入口。测试本身定义跨模块契约且没有更合适的生产入口时，可以选择性放置。

## 读取行为

Agent 在代码中遇到锚点时必须：

1. 解析仓库根相对路径和章节 ID。
2. 在解释、审查或修改锚点所属语义单元前，按 [读取与上下文复用规则](../SKILL.md#读取与上下文复用) 读取或复用目标章节；再次遇到同一锚点本身不触发重读。
3. 补读理解该章节必需的范围说明和直接依赖，不默认读取整篇文档。
4. 发现路径或 ID 无效时把它视为文档漂移。

只读任务报告失效锚点及其位置。获得修改授权的任务修复锚点、文档或二者，但不得凭猜测把失效锚点改指向语义相近的章节。

## 变更规则

- **标题改写**：章节语义不变时保留 ID，代码锚点无需改变。
- **章节重组**：语义身份仍相同时移动原 ID；拆分后为新语义创建新 ID，并逐个判断旧锚点目标。
- **语义替换**：创建新 ID，更新全部代码锚点，再删除没有引用且不再有效的旧章节。
- **代码移动**：锚点跟随语义所有者移动，不在旧位置保留失去上下文的孤立标记。
- **文档移动或重命名**：在同一变更中更新全部锚点、目录和普通链接。
- **文档合并**：把每个旧锚点映射到具体的新章节，不统一降级为文档级链接。
- **功能删除**：先处理仍有效的知识，再删除相关锚点、章节和目录条目。

## 检查

使用 `rg -n '@project-doc'` 枚举锚点，并逐项确认：

- 路径存在且属于文档库。
- 目标文件内存在完全匹配的 `<a id="..."></a>`。
- 同一文件没有重复 ID。
- 路径和 ID 符合命名规则。
- 锚点位于手写语义所有者附近。
- 旧路径和旧 ID 在移动或删除后不再出现。

同时从被锚定章节反向搜索代码引用，确认关键入口没有因重构而丢失锚点。不要仅凭锚点数量判断覆盖质量。
