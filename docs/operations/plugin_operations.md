<a id="deployment"></a>
## 部署前提

插件管理与调度属于单个后端进程。不要让多个后端实例同时管理同一组安装记录和目录。插件以宿主用户运行，独立进程用于隔离崩溃，不提供操作系统沙箱；前端插件也与宿主共享浏览器运行环境。只安装经过管理员审阅的代码。

确保 `plugins.dir` 可写且持久化。默认目录来自 `DATA_DIR/plugins`；新安装文件在 `installed/<id>/sha256-<archive-digest>/`，旧版的 `<version>/` 目录仍可读取，可丢弃状态在 `state/<id>/`，上传暂存位于 `staging/`。宿主重启清理旧上传 token，上传预览最多保留 30 分钟。

保存 secret 配置前，需要固定的 `security.secret_encryption_key`。备份和迁移时保留同一密钥，丢失密钥不能通过重新安装插件解密原值。配置来源和显式引用规则见[进程配置](../interfaces/configuration.md#configuration_sources)。

<a id="installation"></a>
## 安装与配置

管理员在 `/admin/plugins` 的“发现”视图打开插件详情页，直接安装推荐版本，或在“版本”标签里选择其他版本。安装前的审阅弹窗列出权限、平台、发布者和外部主机声明，确认后才会安装；更新记录在详情页查看。签名用于确认索引来源，不代表插件代码已经过安全审计。网络主机列表是作者声明，宿主不强制限制插件出站访问。

上传安装支持 `.tar.gz`，压缩包最多 64 MiB，解压后最多 256 MiB。预览不会执行代码；安装前仍需确认完整权限集合。同 ID 的不同版本自动进入更新流程，默认情况下，同版本上传只用于修复缺失或损坏的上传安装。审阅弹窗提供两个默认关闭的测试开关：“忽略版本检查”跳过插件声明的网关版本上下限；“强制覆盖安装”替换同 ID 的持久化安装，允许不改版本号重新上传。开关相互独立，每次审阅重新选择。忽略版本要求不能补齐网关尚未实现的功能，也不会放宽协议、平台、权限和包完整性检查。

缺少必填配置时安装为禁用状态。填写配置、保存后再启用，并检查运行状态。配置保存与额度保存是两个独立操作；界面报告部分成功时，只重试尚未保存的部分。密钥字段留空或不编辑可保留原值，显式清除动作才删除原值。

额度是安装记录的策略，不随插件版本回滚。0 表示禁止相应操作；订阅与订阅兑换码的套餐白名单默认空，需要管理员明确加入套餐。先用小额度验证领取、重试和失败行为，再按业务需要调整。

<a id="recovery"></a>
## 更新与恢复

索引更新只比较安装时接受的来源。另一个索引中的同 ID 插件不会成为自动候选；来源被删除后，已接受的包地址仍能用于恢复当前安装，但没有来源更新入口。上传更新会把当前来源改为上传，原来源留在上一版本快照中。

更新和强制覆盖先验证目标文件，再切换记录并等待就绪。原安装的启用选择、使用上限和业务数据保留，配置按目标声明迁移；缺少新必填项时拒绝替换已启用的插件。启用的新版本在 30 秒内未就绪或 Init 失败时，宿主恢复原完整记录并重启旧版本。`PLUGIN_UPDATE_FAILED` 带新版本错误和最多 50 行日志；只有 `restored_version` 才表示恢复检查成功，`rollback_error` 表示仍需处理恢复故障。不要只凭数据库版本号判断进程已恢复。

手动回滚交换当前与上一版本的 manifest、配置、密文密钥、权限、来源和包摘要，启用选择及额度保持不变。更新成功后仅保留当前和上一包目录，即使两个包的版本号相同也可回滚。回滚后可再次交换；业务 KV 和资金台账不随代码版本倒退，插件作者必须保持数据兼容。

索引来源的本地包缺失或内容摘要不匹配时，会按已接受 URL 和摘要下载；失败后可修复网络再点“重启”。上传来源不能从网络恢复，需重新上传同 ID、版本和原 manifest 摘要的包。文件尺寸没有变化的内容损坏也可通过这一入口修复。索引 URL 或签名变化不能重写已经接受的归档摘要。

<a id="distribution"></a>
## 索引与网络

内置索引使用源码中的 `plugin.OfficialIndexKeys`，宿主已经内嵌官方公钥；移除全部公钥会拒绝内置验签，不能临时按 unsigned 使用官方来源。[官方索引仓库](https://github.com/TokenFlux/tokenrouter-plugins)维护登记、校验和签名工作流，配置步骤见[发布插件与索引](../guides/plugins/publishing.md)。

自定义索引必须为 HTTPS。设置公钥后，该公钥必须验证签名；没有公钥时，只有不存在 `.sig` 才按未签名来源接受。签名存在但不匹配会标记 invalid，保留此前接受的缓存。`cached_at` 是最后接受时间，`signature_status` 和 `last_error` 是最近尝试的观察，二者可能来自不同轮次。

市场使用一小时缓存，过期时后台刷新；“刷新”立即重试所有启用来源。一个失败来源不会隐藏其他来源的可用条目。修改来源 URL 或公钥会清除旧缓存，避免把旧来源数据归到新信任配置下。

`download_proxy` 用于索引及安装包传输。`download_url_prefix` 只在 GitHub 安装包 URL 前拼接前缀，不改写索引 URL，也不作用于其他下载主机。`plugin_http_proxy` 才用于插件进程的 HTTP_PROXY/HTTPS_PROXY。详细键名见[插件运行时配置](../interfaces/configuration.md)。

轮换官方签名时，先让宿主接受新旧公钥，再切换索引私钥；所有需要的宿主完成升级后再移除旧公钥。私钥只存放在发布系统的 secret 中，不进入源码、日志、索引或浏览器表单。

<a id="emergency"></a>
## 紧急关闭与卸载

将 `plugins.enabled: false` 后重启宿主。插件进程、调度和 KV 维护不再启动，贡献 API、UI 描述与公开资源返回 503 `PLUGINS_DISABLED`，菜单消失；管理员仍可查看和卸载安装记录。此开关是进程配置，网页上的启用开关不能覆盖它。

普通禁用先停止接收新调用，再排空请求和宿主回调。卸载在排空完成后才事务删除安装记录及可选 KV；排空失败时保留安装记录供重试。默认卸载保留 KV，再安装相同 ID 可读取原业务数据。勾选清除数据会删除该插件的 KV，台账始终保留。

<a id="diagnostics"></a>
## 日志与资源

插件列表和详情页页头分别显示启用开关和实际运行状态，详情页概览给出内存、CPU 和重启次数。backoff 会自动重试；10 分钟内第五次异常退出进入 crashloop，需要重启、替换版本或禁用后重新启用。failed 时先检查最新错误、配置与包文件，避免反复启动同一个无效版本。

界面保留最近 500 行进程日志，单行最多 4 KiB；完整宿主日志按 `plugin_id` 和版本查找。RSS 与 CPU 每 30 秒采样，显示值不是实时峰值。`GOMEMLIMIT` 是 Go 运行时软限制，RSS 超过声明额度两倍时只告警。宿主服务的容器或系统资源预算限制整体损耗，当前不提供单插件硬隔离。

超大响应、禁止的 Content-Type 和传输失败由宿主拒绝。脚本或 SRI 失败时前端刷新一次 UI 描述再重试；持续失败只替换插件内容区。插件自身的 401 有独立响应标记，不会触发宿主登录刷新或登出。

<a id="backup"></a>
## 备份与迁移

数据库备份保留 plugin_indexes、plugin_installations、plugin_kv 和 plugin_ledger，即使关闭其他可选备份组也不会排除这些表。上传包无法重新下载，还需单独保留安装目录或原归档；state 目录只用于可丢弃缓存。

恢复时同时核对数据库、固定加密密钥和安装文件。不要把“数据库可恢复”当成上传二进制和插件数据迁移均已验证。插件升级应兼容保留的 KV 与台账，代码回滚不会撤销已经完成的资金、邮件或权益操作。

迁移 306 固定插件签发订阅码的天数；回退到忽略该字段的旧宿主会恢复旧兑换行为，限制见[升级说明](upgrade_notes.md)。
