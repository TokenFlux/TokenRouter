## 凭据刷新

### 后台刷新与热路径协同

后台刷新分页扫描需要维护的提供商，按平台规则筛选候选，并对每个提供商施加独立的并发上限、QPS 上限、单次尝试超时、每轮总超时和有上限的退避。OAuth、Setup Token 和 Qoder COSY 各自维护候选条件；API Key、Bedrock 和 Service Account 通常由请求路径或签名逻辑管理，不一定持有 refresh token。

- 启动与分页：循环启动后立即执行第一轮，周期设有下限。扫描按严格 ID 升序分页，未处理完的页不推进游标，到达最后一页后游标归零。
- 准入隔离：周期刷新与 Grok 管理对账共用每平台准入上限，但两者的连续失败状态互相独立。
- 热路径协同：请求路径在使用 token 前仍检查是否临近过期，并通过提供商级锁避免并发刷新。后台刷新用于降低热路径延迟，正确性依赖共享的凭据版本和 CAS 保护，防止旧请求覆盖新 token。
- 停机语义：停止时同时取消周期循环、分页扫描与按需对账，等待在途任务结束并固定首次停止结果；等待超时不算排空完成。

### 刷新协调与条件写入

请求路径、后台刷新和管理员手动刷新共用同一套刷新协调机制，包括提供商锁、锁内重读、交换前快照、版本写入、条件持久化与竞争恢复。

- 刷新成功：原子更新凭据和过期时间，清理可恢复错误，并同步提供商缓存与调度快照。OpenAI 和 Antigravity 可在刷新后检查并设置隐私状态。
- 失败分级：失败按阈值累计，单次瞬时网络错误不会永久禁用提供商；仅在凭据被明确撤销或归属失效时进入需重新授权状态。
- 非 Grok 成功条件写：在同一事务中按提供商 ID、平台、类型、状态、完整凭据和代理锁行比对，随后清理凭据并写 outbox。管理员已修改或禁用该提供商时，本轮结果不覆盖，调用方重读且不再重换 token。Grok 使用独立的 CAS、持久化后回读和 containment 错误分类。
- 清除临时停调：额外比对本次凭据、代理、状态以及原 cooldown 期限与原因。身份或窗口已变化时，跳过 Redis 清理、快照发布和旧身份维护；清理成功时先写健康数据再发布缓存。清除临时停调本身不触发 Antigravity 缺少 `project_id` 时的恢复流程。
- 非 Grok 失败条件写：比对交换时身份后再写健康状态，避免旧失败覆盖管理员的新配置；同身份已有更长 cooldown 时不缩短，outbox 失败按尽力而为处理。内存快速阻断对刷新失败按凭据身份隔离，提供商级配额和容量阻断保持提供商范围。发布前复核清理版本，迟到通知无法重装已清除的阻断，多份在途凭据的期限互相独立。
- Antigravity 强制刷新标记：在 Extra 与 outbox 事务中复核身份后清除；永久失败时，仅在健康状态条件写入成功后才清除该身份的标记。

### 管理员刷新与停止

单个和批量管理员刷新沿用同一协调器与平台锁键，在锁内重读后执行。凭据写入经过管理校验与行锁身份比对；冲突时直接返回最新提供商，不重复交换也不执行旧结果的后续动作。身份比对字段仅用于内部调用，不接受 HTTP JSON 输入。

手动刷新按五次独立提交推进，每步都校验交换时身份与该步原状态，冲突时立即停止并保留已完成步骤：

1. 清除错误状态。
2. 清除全提供商限流。
3. 清除 Antigravity scope 状态。
4. 清除模型级限流。
5. 清除临时不可调度状态（清理运行时阻断时额外校验原版本，保留之后新安装的阻断）。

刷新协调器停止时拒绝新认领，取消锁等待与在途交换并在预算内等待。已接纳的等待者拿到锁后仍复查停止屏障，避免前持锁者因取消释锁后再次发起交换。若上游交换器忽略取消，停止接口报告未完成，且迟到响应无法写回凭据；正常请求的取消来源不受影响。交换前快照深复制嵌套凭据，并将 `nil` 凭据归一化为空对象后比较。

### 活动时间与到期扫描

- 最后使用时间：单一内存队列互斥处理入队与批次取出。批次写库失败时，仅将尚无更新值的提供商补回队列，避免覆盖较晚到达的活动时间。停止时取消新周期与等待者，待在途批次写完后执行末次 flush，受 10 秒预算和应用剩余退出预算的双重约束。
- 到期扫描：每分钟运行一次，启动后立即执行第一轮；取消与等待受应用生命周期控制，停止后不再扫描。

## 管理操作

### 存储、编辑与字段意图

| 场景 | 写入约束 |
| --- | --- |
| 普通编辑、管理员编辑、影子代理传播、CRS 配置写入 | 显式声明待写字段；在事务内锁行重读最新记录后再合并，避免改名等常规操作覆盖最新凭据、健康状态、调度开关或消费快照 |
| 敏感凭据子键缺省 | 从锁内最新值继承；显式状态恢复仍更新状态与错误消息，CRS 可写入来源状态与调度开关 |
| 配置替换 | 保留 billing 消费累计和专用入口写入的最新快照，固定窗口按锁内累计值在原时点重算 |
| 身份变更联动 | Ollama 身份变更清理受管会话；用量查询身份变更使观测失效；outbox 随配置事务一起提交 |
| 专用运行态字段 | `last_used_at`、全提供商限流、过载与会话窗口仅由专用运行时入口维护 |

消费累计与额度重置 SQL 在外层事务内执行时不自行提交或发布事件；独立入口按"先提交、再发布"顺序执行。字段意图声明不改变数据库、缓存和 HTTP 格式。

### 导入、导出与同步

- 文件导入导出：管理员可选择导出原始凭据，导出自动排除影子提供商并传递隔离副本。导入按"代理 -> 逐项创建提供商 -> 隐私设置"顺序执行，省略和 `null` 字段按创建规则处理；OpenAI ID Token 通过非认证解码补齐缺失的身份提示。
- Codex session 导入：仅含 access token 时按 access 摘要匹配；完整 OAuth 按用户与提供商兼容匹配；Agent Identity 按团队隔离并合并 runtime。导入时的 JWT 解码仅补齐提示、不承担认证；OAuth 批量创建复用相同的合并、保护字段和摘要规则。
- CRS 同步与预览：覆盖六类来源，按既定规则处理部分成功、`nil` 与空选择、影子限制及来源字段清理。Claude、OpenAI、Gemini 导入后执行尽力刷新，复用生产刷新协调器与条件写：锁内确认来源身份，管理员修改优先，取消后不写回，导入成功数不依赖刷新结果。该路径保留原状态资格与令牌版本字段，不套用后台刷新的 active 与过期筛选。
- Grok 导入后探测：按需启动，配备 3 个 worker 和 64 个排队位，按提供商去重；25 秒预算从任务实际开始执行时计时，输入为不含凭据的 `ProviderSnapshot`。停机时取消未领取项并等待在途项，超时报告未完成，取消不算已探测；异步探测失败不回滚创建或导入。

### 批量操作与隐私设置

- 批量操作：批量删除按母提供商与影子依赖排序，并发 5；批量创建、刷新与清除错误支持部分成功和重复 ID，并发 10，按固定顺序返回错误。批量更新凭据字段时先全量校验，再逐个提供商在行锁内提交字段补丁，避免校验时的旧 token 或未选配置覆盖新值；补丁参数不接受 HTTP JSON 输入。
- 隐私设置：停止时取消并等待在途请求，忽略取消的迟到响应不会写回；批量后台入口保留任务完成屏障与任务名称，服务停止后不再发起新请求。写回在 Extra 与 outbox 事务内比对查询时的凭据、代理、状态和影子归属，身份变更时返回无可应用结果且不更新旧模式；不支持条件写的兼容路径不会退回无条件覆盖，普通存储失败按尽力而为记录并返回。

### 列表、Tier 与模型目录

- 列表与运行状态：先分页与服务端排序再采集运行状态；仅明确请求时查询筛选池和分组池评分，并对候选并集批量查负载。评分、并发、会话与 RPM 来自 `scheduler`，详细用量来自 `usage`。OpenAI 自动暂停规则每次读取动态默认阈值，包含窗口豁免、2 小时陈旧界限及缺时间戳处理。
- Google One tier 刷新：支持单个与批量（并发 10）条件配置写入。批量输入为空或损坏时，回落为最多 10,000 条 Google One 查询，单项失败不影响其余项。查询起始固定身份，保存时在行锁内复核并仅合并 `tier_id` 与本轮 Drive 字段；管理员新 token 与未选 Extra 不被覆盖，outbox 失败时回滚配置。
- 管理端可用模型：合并统一目录与提供商配置后检查白名单和执行资格。空白名单允许目录未知型号，Spark、OAuth、站点及协议规则照常检查。测试选择器显示实际模型 ID。Jev 手动测试支持图片理解与 Box 定位，使用提交时的图片与问题快照，默认填入 `jev-latest`；其他平台等待管理员选型，批量测试使用勾选候选并独立初始化默认提示词。
- 多协议与原生探针：Kimi、Zhipu、DeepSeek 各自注册默认模型，固定与多协议探测复用原生协议请求、流读取和 401 错误写入。多协议探测中 Messages 和 Responses 空模型沿用 OpenAI 默认值，Chat 用各平台默认值。
- OpenCode 探针：从提供商快照一次确定最终模型和协议而不重复映射，流式协议复用原生交换，SystemOne 沿用 Jev 决策交换。单次 `TestRun` 保留分组、客户端协议、取消与输出错误。
- 实时模型同步：跟踪在途调用并在停止时取消等待，构造时不访问上游。已保存记录仅使用保存配置，临时凭据预览不持久化；单次查询返回模型与目录建议，人工覆盖留在配置表单。模型预览与提供商测试共用探针任务范围，持久化提供商串行处理。
- Qoder 模型目录：由管理员在已保存提供商上手动同步，启动、凭据刷新和日常推理仅复用已保存目录。查询失败保留上次同身份快照，有效空列表清空候选。模型属性随同步展示，白名单草稿由管理员保存；目录中消失的名称留在白名单内，显式映射目标可指定自定义路由，见[Qoder 原生上游](../interfaces/qoder_upstream.md#模型别名与映射)。
- 调度诊断与执行目标：高级调度诊断以只读安全数据调用 `scheduler` 同一评分算法。执行目标由提供商记录和路线计划组成，复制时保持自引用关联与 map 隔离。

## 状态与临时不可调度

健康管理负责通用错误规则匹配、显式错误与池模式优先级、认证失败与过载转换、403 累计冷却、CN 可恢复冷却、429 默认回避、流超时计数阈值以及提供商和模型额度阈值判断。持久化、缓存和调度反馈保持固定顺序，缺失的可选仓储按原样跳过。

- 平台专项状态：Anthropic 限流响应头驱动 5 小时会话窗口、提供商耗尽窗口和 Fable 模型级窗口，被动采样按独立写入顺序执行。OpenAI 图片错误按池模式与错误码触发图片能力冷却，不升级为全提供商限流。401 母提供商处理、图片和模型冷却、API Key 滚动熔断以及进程内去重的 Team 联动各按独立用例维护。
- 状态分层：长期状态、`schedulable`、全提供商限流、模型限流和临时不可调度相互独立，不互相替代。

| 状态类型 | 触发条件 | 调度与恢复行为 |
| --- | --- | --- |
| 可恢复错误 | 凭据或配置错误 | 记录为 recoverable error，需人工重新授权 |
| 临时窗口 / 限流 | 429、明确 reset 时间、短期网络或上游故障 | 设置恢复时间，到期前过滤提供商或模型 |
| 策略 / 代理不可用 | 管理员策略或代理过期 | 临时移出调度，不删除提供商 |
| 到期暂停 | 提供商到期 | 维护任务自动暂停；重新启用前需验证凭据与关联资源 |

所有状态写入均附带凭据快照或版本条件：较早请求无法在新凭据生效后写入旧错误，恢复动作也无法清除另一请求刚确认的永久错误。

## 提供商测试与自动恢复

管理端即时测试、定时测试计划（`scheduled-test-plans`）与分组后台探测共用同一测试事件流水线。HTTP 入口以 SSE 输出并逐事件 Flush，后台入口汇总类型化事件；写出失败时返回写入错误并取消执行，同时保留事件顺序与已产生的部分输出。

- 定时测试计划：构造时不启动；每分钟触发一轮，偏移 10 秒，每轮最多 10 个测试，总预算 5 分钟。停止时取消偏移与槽位等待并等待在途测试（超时报告未完成），停止后不可再次启动。
- 自动恢复：恢复按独立写入顺序执行，缓存删除尽力而为（不包在单事务内），且不改变人工 `schedulable` 开关。计划配置自动恢复时，测试成功可清除符合条件的错误、限流、临时停调和模型限流，但管理员禁用、提供商过期或类型不匹配仍维持原状。
- 平台测试分支：
  - Qoder：按账号目录和白名单选型；空模型优先已启用的默认项，空提示使用简短 Python 加法函数任务，输出上限 256 tokens。
  - Gemini：区分 API Key、AI Studio OAuth、Code Assist 和 Vertex 四条路径。
  - Anthropic、Vertex、Bedrock：按最终上游型号读取所选分组的采样属性后再构造测试报文，各平台自行处理认证与签名区域。
  - Grok：区分文字与图片端点，共用同一套健康写入规则。
  - OpenAI：包含 Responses、Chat、两种 Compact 与图片分支；OAuth 图片测试使用生图主控模型设置并在开始事件展示主控与图片型号，见[OpenAI 上游](../interfaces/openai_upstream.md#responses-请求细节)。
  - 国产平台：按固定协议或自适应顺序探测。
- 探测运行约束：每次自动探测携带独立 UA；OpenAI 自动探针与网关共用 UA 优先级和浏览器回退策略，每次判断读取动态设置。429 解析结果回写窗口恢复时间和观测套餐，影子提供商不持有套餐凭据，缺少重置信号时不写窗口状态。管理测试的 Qoder 会话具备独立停止清理钩子；Antigravity 探针与转发共用平台重试与 credits 状态。
- 诊断边界：单次模型测试成功仅代表该路径当前可用，不代表所有 endpoint capability 或媒体资格正常；失败必须区分认证、模型、配额、代理、TLS 和上游容量，避免自动恢复反复启停。

### 测试和额度探测的用量记录

测试与主动额度探测使用专用 `SystemUsageTransport` 包装共享传输，每次派发模型请求固定提供商和倍率并生成独立请求 ID。

- 观测与取消：在响应读取过程中记录用量，保持 SSE 预览输出；解析器提前结束时，关闭响应最多继续读取 2 秒以提取末尾用量。已取消请求保留已观测到的部分。
- 异步记账与重试：记账提交至应用生命周期任务组，避免数据库等待影响探针结果与耗时；停机等待已接收任务，停止接收后回落为同步写入。写入使用独立 5 秒预算，最多重试 3 次，不重调上游模型。
- 来源与去重：手动测试、定时测试和分组探针显式传递来源；Grok 主动额度探测与 OpenAI Codex 快照探测在真正执行的共享调用内建立来源，缓存命中与 singleflight 等待者不重复记账。余额、模型目录、授权刷新和内容审核不进入该路径。记录仅含计数、金额、模型、端点和状态，不含提示词、响应正文、图片或凭据。
- 限额门禁：自动模型请求派发前检查提供商本地日、周、月及总消费限额，达限跳过；手动测试不受阻断以便诊断，费用继续累计。失败请求保留已观测用量，缺失费用显示未知。资金与去重细节见[系统模型调用成本](../domains/routing_and_billing.md#system_model_cost)。

### 测试参数与协议解析

- 分组探针固定协议：复用网关 `RoutePlan` 和分组单步转换规则，重新确认提供商仍启用该路线后按上游协议构包。Messages、Responses、Chat 执行文字探测；Gemini 原生按输出属性选择文字或图片；图片生成要求图片能力；SystemOne 执行决策探测；Grok 支持 Responses 与图片生成，解析到原生 Chat 的候选不可用于指定协议探针。
- 属性会话一致性：指定协议探针的候选筛选、能力判断和采样参数共用同一次属性会话，分组配置读取失败即终止请求。图片声明不会把文字入口改到图片端点，多协议 API Key 测试仅执行解析出的单个端点。未指定协议的旧配置维持自动行为，手动测试的 `protocol` 参数保持提供商协议选择含义。
- `group_id` 与模型属性：单次、批量和决策测试均可传 `group_id` 选择模型属性（弹窗默认列表筛选分组或首个所属分组），省略或未分组用默认属性。管理测试仅做提供商映射，分组后台探针按分组映射后的最终上游型号读属性，属性读取失败即终止请求。
- 平台端点与属性匹配：OpenAI API Key 和 Grok 图片能力按图片生成端点查属性，自动文字探针按实际文字端点查询并匹配协议限定规则。OpenAI 属性查询与发送共用协议选择（显式测试协议优先于文字路由）；Grok 自动图片探针读所选分组属性，显式文字测试保持 Responses。
- Kimi、Zhipu、DeepSeek 测试：仅测试 `upstream_protocols` 中已启用的原生端点，集合为空直接报错。`protocol=chat_completions|anthropic|responses` 指定单个已启用协议（未启用则在请求前失败）；省略时按 Chat、Messages、Responses 依次验证。
- 自定义中继复用：测试复用自定义 Base URL、代理、TLS 指纹和受保护 Header Override。自定义 Anthropic 中继在模型同步等 OpenAI 格式请求中仅去除末尾 `/anthropic`，保留 host 和前缀路径。
- `test_type` 与提示词：连接测试显式传入 `test_type=text|image` 和自定义 `prompt`。文字测试不因模型名含图片标记切端点，图片测试走 OpenAI、Gemini 或 Grok 图片端点（不支持平台直接报错）。
- 缺省类型与 Compact：OpenAI `compact` 与 `legacy_compact` 仅发固定载荷；省略 `test_type` 时按最终模型输出属性选择，输出未知则要求显式指定或补齐属性。
- 图片响应校验：图片与文字结果分别经 SSE 图片和内容事件返回。OpenAI API Key 与 Grok 接受 `b64_json` 和图片链接（OpenAI 仅允许 `https` 或 `data:image/`）；OpenAI 原生 JSON 先经共享校验，HTTP 200 错误体、空数组、损坏条目或无展示链接均判失败并附截断正文。

## 额度与能力探测

各平台维护独立的上游额度快照（OpenAI/Codex 窗口、Gemini tier 与模型额度、Antigravity credits、Grok 计费与媒体资格、Qoder Credits、Kimi/Zhipu/DeepSeek 统一用量快照等），用于调度、容量展示与诊断，与 TokenRouter 用户余额或订阅账本无关。

- Gemini 配额与预检：静态默认值与动态设置合并缓存，每次请求获取私有副本。本地预检单独缓存 1 分钟日统计（分钟级实时查询），采用洛杉矶时区日界，与展示用的固定 24 小时窗口相互独立。
- OpenAI 额度快照：重置次数查询将带到期时间的完整结果存为展示快照；若上游只返回正数次数而缺到期明细，实时返回调用方但保留旧快照。
- OpenAI 重置恢复：直接调用重置 API 消费次数后，在脱离客户端取消的有限上下文中恢复错误、限流与临时停调（不改人工 `schedulable`），再回读快照与提供商。部分失败用 `cache_refreshed`、`provider_state_recovered` 和 `warning_code` 区分，已消费次数不可重试。
- Codex 邀请汇总：资格接口失败时仅关闭邀请入口，已有次数查询仍按顺序继续。
- OpenAI 能力配置：API Key 不自动探测 Responses，以管理员所选协议为准，写入时清理历史探测字段并规范化两种压缩开关。手动测试不改能力配置，仅正常记录额度、401 和 429；HTTP continuation 为独立开关，默认关闭。
- OpenAI 测试模式：API Key 文字测试可选 Responses 或 Chat Completions，OAuth 用 Codex Responses。API Key 生图测试读取端点模式，仅流式时传 `stream=true`、`partial_images=0` 并共用流聚合读取器，手动与定时测试一致且失败不换模式重发。
- 调度传播：调度数据保留原生协议集合、认证方式、两种压缩开关和 continuation 设置，随提供商失效机制传播；国产供应商不写回旧 OpenAI 文本路由镜像。
- 历史键清理：通用上游声明倍率探测已停用，所有写入路径丢弃 `upstream_billing_probe` 与 `upstream_billing_probe_enabled`（不影响 Ollama Cloud、endpoint capability 或其他额度状态）。
- 失败降级与 API Key 展示：实时探测失败时保留上次成功快照并同时展示当前错误，旧数据不标为实时；配额耗尽或能力变化时失效相关调度数据。API Key 上游用量查询仅用于管理员展示，不影响调度、自动暂停、倍率、本地配额或结算；国产供应商可选周期监控会写快照并触发临时停调，详见[API Key 上游用量查询](../interfaces/upstream_usage.md)。

## OAuth 用量查询

### 统计弹窗与查询缓存

- 统计弹窗 SQL：在单次 `GROUPING SETS` 查询中同时汇总日期、模型、入站端点和上游端点，平均耗时按非空耗时记录数计算，并分别返回提供商成本、用户扣费和标准费用（基于原始用量记录）。查询在专用只读事务内执行 `SET LOCAL jit = off`（事务结束自动恢复），减少高行数估算时的 JIT 编译开销。
- 命名空间缓存与并发：批量 OAuth 用量查询并发上限为 6。Anthropic、Antigravity、Qoder、窗口统计以及 OpenAI/Grok 探测各有独立命名空间、key、TTL、负缓存与 singleflight，每次返回请求私有的展示副本。
- 本地统计与回退：今日展示统计优先批量读取，失败时按并发 8 逐个回退。OpenAI OAuth 本地 5 小时与 7 天统计在单条 SQL 中合并扫描（起点取两个窗口起点中较早者，基于有效重置时间或当前时间减窗口长度，未来时间记录照常计入），返回两个独立副本；不支持合并或失败时回退为分别查询并保留成功项，请求取消即停止回退。
- 停机跟踪：停止登记覆盖外层请求、Antigravity/Qoder 独立查询和 OpenAI 异步快照写回。共享抓取独立于调用方取消，停机时取消并等待（超时报未完成，重复停止返回首次结果）。
- Grok 并发探测与免费额度：Grok 管理探测与每 6 小时模型目录同步共用探测运行时，关库前等待完成，同 key 合并，预算 25 秒和 15 秒，执行时复制提供商记录及嵌套额度与 Header。调度免费额度统计异步执行并纳入后台完成屏障。

### 条件写回与身份隔离

- 查询后错误恢复：仅清理与观测一致的凭据、代理、状态和原错误，单条条件更新提交后再尽力发布 outbox，防止迟到恢复撤销管理员新设禁用或错误。批量查询中缺失提供商与查询失败共用同一结果写锁。
- Qoder、OpenAI、Anthropic 条件写：Qoder 与 OpenAI 写回比对平台、类型、状态、凭据、代理和影子归属；Qoder 清除限流额外比对原限流与 overload 窗口，快照与健康各自提交和通知。Anthropic 主动查询回写被动 Extra 时比对身份，窗口列另比对旧结束时间，两步各自提交（观测 Extra 仅同步单提供商快照，窗口列尽力发布 outbox）。
- 缓存与持久化身份隔离：Qoder、Antigravity、Anthropic 内存缓存与共享返回带进程内来源标识，身份变更不复用旧缓存并隔离负缓存。Qoder 持久化额度快照携带站点、账号和组织身份摘要，上游失败时仅展示身份匹配的上次快照。

### Ollama Cloud 用量维护

Ollama Cloud 共享浏览器会话、按 API Key 身份分组、手动刷新、周期资格、singleflight、成败快照及重试调度归 `provider` 维护；Cookie 校验与白名单归 `egress`；固定 URL 请求、重定向阻断与 HTML 解析归 `upstream/ollama`。

- 生命周期：同时跟踪启动后立即执行的首轮、每分钟扫描和管理员手动查询。停止时取消排队、周期锁等待与在途操作并在应用剩余预算内等待，超时报告未完成，重复停止保留首次结果；调用方或停机取消后迟到响应不写快照。
- 租约策略：Redis 租约竞争时跳过，Redis 故障时回退数据库，无后端时直接执行。

原生查询适配器不决定健康与调度，边界见[原生查询与提供商编排](../interfaces/upstream_usage.md#native_usage_adapters)。

## 运维诊断

- 按每个提供商分别观察候选数、刷新成败、节流、超时和最长积压，避免仅看全局成功率。
- 关联提供商测试、刷新、配额探测、代理健康和调度过滤原因，区分凭据故障与出站网络故障。
- 核对数据库状态、Redis 快照与进程内缓存是否一致；手工修改数据库后需等待周期重建生效。
- 自动恢复或批量导入后抽查实际推理协议；token 端点可用不代表推理端点可用。
- 排查 OpenAI Chat 时，同时核对入站协议、`upstream_protocols`、分组 `protocol_fallbacks` 和 Usage Log 的 `upstream_endpoint`；默认模式记录 `/v1/chat/completions`，历史探测状态不改变上游协议。
