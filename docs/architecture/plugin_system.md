<a id="single_instance"></a>
## 单实例前提与信任模型

插件系统遵循项目的单实例部署约定：一个后端进程和一个前端实例，宿主前后端整体升级。进程管理、运行状态、回调限流和开发目录加载由这个后端持有，不通过 Redis 协调。

插件是管理员信任的代码。独立进程用于隔离崩溃和卡死，不构成文件、网络或操作系统用户沙箱。宿主不继承整份环境变量，也不把数据库凭据交给插件；同用户运行的恶意代码仍可能读取宿主用户可访问的数据。`GOMEMLIMIT` 只是软限制，RSS 超限会记录告警，硬限制由部署层负责。

<a id="process_lifecycle"></a>
## 进程生命周期

`plugin/provider.Processes` 持有每个插件的监管器。构造不启动进程；管理调用创建监管循环，依次完成二进制摘要校验、go-plugin gRPC 握手、AutoMTLS 回调通道和 Init。插件就绪后才允许获取租约。

正常关闭先进入 draining，拒绝新的租约，最多等待 10 秒排空，再调用最多 5 秒的 Shutdown，最后终止进程。应用的 PluginRuntime hook 在启动顺序 976 登记，停止阶段为 27，应用关闭时使用总计 8 秒的预算；更早的 HTTP 阶段已负责排空请求。预算到期会取消子进程，不继续等待插件自行配合。

进程退出或连续三次健康检查失败触发重启。默认退避为 1、2、4、8、16、32、60 秒，之后保持 60 秒；10 分钟内第五次异常退出进入 crashloop，等待管理员重启、版本替换或禁用后重新启用。每 15 秒检查健康，每次 3 秒，每秒检查退出，每 30 秒采样 RSS 和 CPU。

Linux 和 macOS 使用独立进程组，取消时先终止同组后代；Linux 另设 `Pdeathsig=SIGKILL`。进程执行器持有 stdout/stderr 的宿主读端，强制关闭时主动关闭这些句柄，避免后代继承管道后使传输清理无限等待。Windows 保留直接子进程终止，同样关闭宿主读端。SDK 每两秒检查父进程：Unix 检查父 PID 是否变化，Windows 持有原父进程的同步句柄并检查退出状态，避免父 PID 保留或复用造成孤儿进程。Unix socket 使用宿主创建的短临时目录，避免较长的数据目录超过平台 socket 地址限制；目录随该代进程清理，启动失败也会删除。这个协议目录与插件的 HOME、TMPDIR 分开，后两者仍在该插件的 state 目录内。

<a id="leases_and_callbacks"></a>
## 租约与宿主回调

`Runtime.Acquire` 不等待启动或容量；不可用、正在排空和超过 32 个在途租约分别返回对应错误。每个租约固定连接代次和版本，归还操作只执行一次。旧进程退出后才完成的请求不会改变新进程的租约计数。

每个进程代次另外跟踪宿主回调，因为插件自己的后台 goroutine 也能调用宿主。停止和异常重启会关闭回调准入，取消剩余调用，并等待处理器实际返回；收到取消信号不等于数据库操作已经结束。管理请求超时会返回失败，清理继续等待，重试只能在这些调用结束后成功。卸载在这一步之后事务删除安装记录和可选 KV，避免排空期间重新写入已清除的数据。

宿主回调服务绑定安装时授予的权限，不从插件请求中获取权限集合。已知无需权限的方法、受限方法和未知方法分开处理，未知方法拒绝执行；回调总量使用每插件每秒 100 次、突发 200 的令牌桶。钱包、兑换码、直接订阅、邮件、验证码、KV 和只读能力均通过已绑定的宿主服务执行。写调用的审计覆盖权限、限流、排空拒绝和成功重放，记录插件版本及可验证的调用用户，不保存 grant 或配置内容。

插件日志转入宿主 slog 并带插件 ID、版本，每行最多 4 KiB，每插件限速 200 行/秒，保留最近 500 行。监管循环汇总被丢弃的日志数量；日志缓冲与进程重启配合保留诊断，不写入数据库。

<a id="http_contributions"></a>
## HTTP 贡献与资产边界

app 把现有 JWT、管理员认证、Backend 模式门禁、面板限流、安全客户端地址和请求语言读取器装配给 plugin/httpapi。代理先匹配不可变 manifest，再执行对应认证链；公开 API 和静态资源显式使用公网 IP 限流。HTTP 和定时任务通过核心接口调用进程，gRPC 消息和错误细节留在 provider，HTTP 层不会自行解析 JWT。

路由选择与取得进程租约可能跨越一次更新。代理会同时核对租约版本和当前 manifest 摘要，再按之前选中的路由执行。卸载和禁用通过普通租约排空；禁用意图提交后立即更新内存可见性，即使排空失败，UI 描述也不会继续把安装标记为启用。

资源读取只访问已接受的本地文件元数据，不触发包恢复下载。os.Root 限制文件解析范围，固定长度 reader 防止打开后文件增长扩大响应。UI 发现只检查脚本和样式的存在及尺寸，浏览器依据 SRI 验证内容；可选菜单 SVG 限量读取后交给现有前端净化流程。接口细节与允许的 MIME 见[HTTP 贡献与公开资源](../interfaces/plugin_contracts.md#http_contributions)。

<a id="frontend_host"></a>
## 前端宿主

宿主与插件共享一个 Vue 运行时。资源加载器先等待所有样式成功，再插入携带 `data-plugin-id` 和 SRI 的 IIFE 脚本；注册必须发生在该脚本同步执行期间。加载键包含版本、URL 与完整性摘要，资源请求也附带摘要参数，允许同版本修复绕过旧的 immutable 缓存。失败或超时会释放本次资源，替换成功后才移除该插件的旧样式。

UI 描述按登录账号、角色和语言隔离；在途读被代次保护，旧账号响应不能重新发布菜单。全局禁用清空贡献，其余读取失败保留同范围的旧菜单供恢复。页面匹配精确 audience 与 manifest 路径。脚本加载失败会刷新一次描述再重试一次，最终错误和组件异常只替换内容区，保留导航外壳。路由或发现结果变化后，旧加载结果不能覆盖新页面。

HostApi 通过现有客户端发送限定插件命名空间的请求，保留插件自有 JSON 数据，继续使用宿主会话刷新。导航只能指向当前插件、当前 audience 已声明的页面。用户字段只有 ID、用户名和角色；页面销毁或账号身份变化后拒绝新请求。每个挂载只保留一个确认问题，替换和销毁均按取消处理。

SDK 控件复用宿主原生实现；对话框的 Teleport 面板携带插件样式作用域。页面可以注册 Vue 对象组件、函数式组件或返回 Promise 的加载函数。宿主与开发 mock 使用相同适配器，由 Vue 在渲染上下文中调用函数；同步结果保留响应式跟踪，Promise 交给有超时限制的异步组件并复用首次加载结果。主题变量引用现有按钮、卡片、输入和状态颜色。验证码读取站点配置后选用原有提供商组件；确认未启用时发出空票据，读取失败或配置不全时提供重试，腾讯票据保留 ticket 与 randstr。插件代码仍是管理员信任的浏览器代码，HostApi 的接口范围不构成 DOM 或存储沙箱。

插件的 `--tr-color-brand` 对应主按钮填充色 `primary-600`；链接、选中页签和选择标记使用 `--tr-color-accent`，浅色为 `primary-600`，深色为 `primary-500`。兼容尚未提供 accent 变量的宿主时，插件按响应式 `host.theme` 选择同一组标准色值，不能把按钮填充色直接当作深色文字色。

<a id="installation_state"></a>
## 安装记录与本地文件

迁移 305 创建索引源、安装记录、KV 和台账表。`plugin/postgres` 通过共享 Ent 连接执行手写 SQL，并参与上下文中的事务。安装记录保存当前及上一版本的完整快照，包括来源、原始 manifest 摘要、平台包、配置、密文密钥、已确认权限和网关版本检查例外；额度属于安装记录，不随版本交换。

`Manager` 在启动时异步按插件 ID 调用 `Sync`。启动时先完成开发源身份登记，防止管理安装与开发目录发布同 ID 的记录。管理用例在写库前取得同一把插件锁，并持有到本地调整结束；不同插件仍可并行处理。发布的安装快照供请求读取，进程容量另用共享锁预留，开发和持久化安装共用 `max_running`。单个安装失败保留记录及错误，其他安装继续启动。

上传预览限制归档大小并校验内容，返回有效期 30 分钟的 token。安装先检查兼容性、全部权限确认和配置，再校验、解压并发布本地文件，最后保存安装记录。缺少必填配置时保存为禁用；保存成功后的进程启动失败仍返回安装结果及错误状态。`staging` 在宿主重建包存储时清空，过期上传每 10 分钟清理。

`installed/<id>/sha256-<archive-digest>` 的标记绑定归档、manifest、二进制摘要及资产 SRI。同版本的不同构建使用独立目录，强制覆盖不会改写回滚包。旧的 `installed/<id>/<version>` 目录继续按已接受摘要读取，在不再被当前或上一包引用后清理。安装与恢复时核对全部保留文件的内容摘要，文件长度不变的损坏也会拒绝复用；普通资产读取仍只检查元数据与读取边界。索引来源缺失或损坏本地文件时按已接受的 URL 和摘要重新下载；仅允许 HTTPS，限制重定向、大小和时间，GitHub 下载前缀只适用于声明的两个 GitHub 主机。上传来源缺失或损坏文件返回 `PLUGIN_PACKAGE_MISSING`，管理员重新上传相同 ID、版本和 manifest 摘要的包进行修复。修复先排空旧进程，保留配置、权限、额度及 KV，再发布新文件身份。

卸载先关闭请求准入并排空宿主回调，然后在同一事务里删除安装记录及可选 KV，最后删除管理目录。排空失败保留安装记录；文件清理失败可重试。台账始终保留，以便后续安装继续识别已执行的幂等键。

管理员在 `/admin/plugins` 目录页启停插件，在 `/admin/plugins/:pluginId` 详情页查看运行状态、采样资源、配置、额度、日志和版本，在 `/admin/plugins/sources` 管理索引来源。操作复用现有 TOTP step-up 开关与验证流程。全局插件关闭时保留查看与卸载入口，执行和新安装控件不可用。上传先返回未执行的包预览，随后确认完整权限集合并安装；需要配置和进程启动失败分别呈现，不能用“已安装”替代“运行中”。

<a id="catalog_updates"></a>
## 索引与更新

`CatalogService` 由 `PluginCatalog` hook 在启动顺序 974 登记，先确保内置来源，再开放管理接口。内置记录的 ID 和管理员启用选择跨重启保留；配置 URL 改变时清除旧缓存。自定义来源可以设置 Ed25519 公钥，修改 URL 或公钥也会清除旧缓存。删除来源只解除安装记录的当前及上一版本索引外键，已经接受的包地址与摘要继续保留。安装快照保存与来源删除通过数据库行锁协调；保存旧快照时，已删除的来源保持空关联，因此更新失败恢复不会重新写入失效外键，也不会丢失旧版本内容。

`provider.IndexClient` 通过下载代理读取 HTTPS 索引和相邻 `.sig`，总预算 20 秒，文档最多 8 MiB。内置来源必须由 `OfficialIndexKeys` 验证，自定义固定公钥必须匹配；无公钥的自定义来源只有在签名文件不存在时才能按 unsigned 接受。签名存在但无效、传输失败或 schema 无效都保留旧缓存。宿主内嵌官方索引公钥，私钥由官方索引仓库的 INDEX_SIGNING_KEY secret 管理；空公钥集合仍会拒绝内置验签。

市场读取首次等待没有缓存的来源，超过一小时的有效缓存先返回，再后台刷新。同一来源共享正在执行的刷新；单个等待者取消不终止其他等待者的传输。来源修改、删除和缓存发布共用来源锁；停止时封闭准入，取消刷新并等待实际返回。`signature_status` 表示最近尝试的验签观察，`cached_at` 表示最后一次接受文档的时间，失败状态可能与仍可使用的旧缓存并存。

条目以索引 ID 和插件 ID 联合标识。普通安装拒绝同 ID 的其他来源；管理员明确选择强制覆盖时，安装接口可切换来源，更新接口仍固定当前索引。推荐版本是最高的兼容、未撤回稳定版本。预发布版本可以在详情中显式选择。已安装来源的下架条目和当前版本撤回原因仍可查看；安装列表只读取缓存注释，不让进程状态轮询等待网络。宿主先检查较新 manifest 的最低宿主版本，再决定是否执行严格解析，因此未来贡献可以显示为不兼容，不会让整个来源不可用。

更新和强制覆盖共用替换流程，先验证目标包，再保存新的当前快照和完整上一包。强制覆盖保留安装的启用状态、使用上限、KV 和台账，并允许同版本的不同归档。忽略版本检查只排除 HOST_TOO_OLD、HOST_TOO_NEW 两项，完整 manifest 仍须通过当前宿主的严格解析；该决定随快照保存，新一次替换默认重新检查。配置按目标 schema 迁移，普通与 secret 类型互换时不继承原值；启用的插件要求迁移结果完整。新版本就绪前保留原当前和上一版本目录；启动失败或 30 秒内未就绪时，以独立恢复预算保存整个原安装记录并重新启动旧版本。失败响应包含新版本错误、最多 50 行日志，以及已恢复版本或恢复失败说明。禁用安装只更新记录和文件。

手动回滚交换完整快照，额度和启用选择保持不变。被恢复的上传包丢失时，安装保留在该版本的失败状态，管理员可重新上传相同版本和 manifest 摘要进行修复。就绪后仅保留当前和上一版本目录；失败更新不会丢掉原先的回滚目标。

<a id="configuration_secrets"></a>
## 配置与密钥

配置经过 manifest schema 校验后，普通值和 secret 分开保存。secret 使用应用共享 AES-GCM 加密器，保存非空密钥要求固定的 `security.secret_encryption_key`。GET 仅返回每个 secret 的 `{set: true|false}`；PUT 省略 secret 保持旧值，空字符串清除。禁用安装可以保存未填完整的配置，启用前必须通过完整校验。

配置保存后通知运行中的插件。配置通知不受普通请求容量上限阻挡，但仍计入该代进程的在途数量和排空等待。监管器记录期望配置，各代记录成功应用的配置，失败通知不会使后续相同值重试被跳过；启动期间修改配置会替换旧代，避免旧 Init 输入覆盖新意图。未改值的协调保留原有 backoff 或 crashloop 状态。没有实现 `ConfigChanged` 时重启；回调失败保留已保存的配置并记录警告。版本配置迁移保留旧快照，并禁止把旧 secret 自动搬入新普通字段。配置写入的审计正文和 MCP 确认预览整体隐藏动态值，避免依赖插件作者选定的密钥名称。

管理配置页按插件 ID、版本和 manifest 摘要隔离编辑状态。更新或回滚后丢弃旧草稿并重读配置与密钥存在标记，旧读取、保存结果和待确认的 step-up 不能覆盖新页面状态。普通进程状态轮询保留当前草稿。

<a id="write_capabilities"></a>
## 写能力与余额台账

`Grants` 从持久 JWT secret 派生专用 HMAC 密钥，票据绑定插件、用户和五分钟有效期。钱包扣款需要当前有效的本人票据；加款可以面向任意已有用户，附带的有效票据只用于审计调用者。重启后相同密钥仍能验证未过期票据。

钱包请求先校验权限和参数，再进入 PostgreSQL 的插件级 advisory transaction lock。相同插件的幂等键跨能力共享，已存在的键先比较规范化业务内容，再返回原始结果。金额以八位小数整数单位规范化，临时 grant 不参与比较，更新票据后可以重放同一笔扣款。幂等重放先于额度检查，因此后续调低额度不会改变已提交结果。

新操作在同一事务里读取安装额度、检查宿主时区自然日统计、调用 `BalanceStore.AdjustBalance` 并写入 `plugin_ledger`。统计时点在取得锁后确定，记录也使用这个时点；等待跨越午夜不会混用两天。任一步失败都回滚余额和台账。加款不增加 `total_recharged`，也不触发直接充值返利；余额调整沿用现有非负结果约束。

提交后才清除用户认证缓存、余额缓存，并通过 `RecordAdjustment` 写入 `plugin_balance` 历史。后续操作使用独立的五秒预算，失败只记录诊断，重放不会重复写历史。台账是资金效果的权威记录。用户及管理员余额历史显示插件来源和 `[<pluginId>] <reason>`，普通兑换码的内部备注继续隐藏。

直接订阅发放要求 `subscription.grant`，并同时检查安装额度中的套餐白名单、单次天数、单用户每日次数和总次数。白名单默认空，未配置就不能发放。发放复用 `AssignOrExtendSubscription` 的当前套餐额度、有效期规范化和排队规则，保留 `AssignedBy` 与 `SourceOrderID` 为空。用户行先按未删除条件锁定，再在同一台账事务中发放；提交后清除用户认证缓存。

邮件要求 `notify.email`，以同一台账先提交 `pending` 认领和额度，再调用通知服务。所有认领都计入每日次数，包括退订、无邮箱、发送失败和结果不明；相同键的调用等待原调用实际返回并保存结果，等待取消不改变原认领。发送完成记录 `completed`，成功和跳过分别保存 `delivered=true/false`。发送器调用前的错误记录为 `failed`，同键重放原错误。SMTP 调用后失败、重启留下的认领或最终结果保存失败都返回 `EMAIL_DELIVERY_UNKNOWN`，不会自动重发。结果写入使用独立的五秒预算；通知成功标记失败但 SMTP 已确认时，仍可在插件台账中保存已送达结果。

邮件幂等键按原始字节区分大小写与标点。通知层的投递标记使用独立命名空间和原始键的 SHA-256 摘要，避免通知键的规范化合并不同操作。旧台账仍决定已认领操作是否重放或返回结果不明；新的认领不读取旧的、可能发生碰撞的通知标记。

兑换码签发要求 `redeem.issue`，只允许余额、并发和订阅类型，固定单次使用且不要求付款历史。码值由持久 HMAC 密钥和插件 ID、幂等键确定。额度检查、普通兑换码创建与台账插入处于同一 Ent 事务，失败一起回滚；创建操作本身不改变用户权益。

订阅码默认天数在重放判断之后、事务之内解析并校验，保存到可空的 `redeem_codes.validity_days`。请求中的 0 保留在幂等意图中，实际天数另存台账结果，因此套餐改长后不会增加已发码权益，也不会影响原请求重放。订阅码没有金额面值，台账 amount 为 0；余额码和并发码记录各自面值。普通兑换继续使用原入口，包括余额码的累计充值与适用返利。

<a id="read_capabilities"></a>
## 只读能力与字段范围

`Queries` 在调用业务读取器前检查权限、用户 ID、批量数量和时间范围。`user.read` 与 `wallet.read` 分开授权，用户邮箱还需要 `user.email`。精确邮箱查找同时需要 `user.lookup` 和 `user.email`；身份绑定只返回第三方记录及标准化的 `username`、`display_name` 元数据，不返回本地邮箱身份或任意上游 claims。

用户精确查找经 identity 核心进入专用 SQL，按 ID、用户名或邮箱三选一。用户名按原值相等比较，邮箱用 LOWER 相等比较，百分号等字符不会变成通配符。查询排除已删除账号，按 ID 返回最多 100 条资料，并直接连接头像记录；它不会进入管理员按备注和 API Key 搜索的查询。

`usage.self` 需要匹配当前插件和目标用户的有效 grant；`usage.read` 可以读取任意目标。批量查询最多 100 个 ID，统计范围不超过 93 天，排行最多 100 行。费用使用实际用户扣费值；summary 保留用户仪表板的本人及当前拥有团队口径，batch 沿用按调用人统计的费用入口，并补充同时间范围的请求与 token 计数，包括零费用记录。排行保留现有公开名字遮罩，网站排行开关不限制插件权限。

订单每页最多 50 条，仅映射协议声明的字段。amount 保留原订单字段的数量或价格含义，不代表支付通道的实付金额，也不统一换算为 USD。充值资格判断使用钱包的累计充值字段。模型目录复用公开端点的 DTO 和成功 envelope；可用分组复用原权限筛选及用户倍率覆盖，包括显式的零倍率。

<a id="kv_storage"></a>
## KV 存储与维护

KV 的命名空间取自进程绑定，RPC 只能指定 collection 和 key。写入在完整键身份的 advisory transaction lock 下检查版本，现有行同时加行锁；替换使用条件 UPSERT，自增使用同一条语句更新值和版本。过期数据对读取和条件判断视为不存在，但物理行尚未清理时，新写入继续递增原版本。清理跳过被锁定的行，避免在版本检查与替换之间删除记录。

配额按物理行统计，每插件最多 50000 个键、64 MiB 的 JSONB 文本与 key 字节。单个后台 worker 启动后立即采样，此后每 5 分钟采样；失败保留上一次完整结果，首次成功前允许新增，因此这是软限制。达到任一上限时拒绝新增逻辑键，已有未过期键仍可修改或删除。过期行在实际删除前占用统计额度，过期键复用按新增判断。

同一 worker 每 10 分钟清理过期数据，每批最多 1000 行，单轮预算 30 秒。每批独立提交；取消或错误不会恢复之前已删的数据。`PluginKV` 在启动顺序 975 登记，早于插件进程协调；关闭与进程同处阶段 27，并等待后台操作实际返回后释放数据库依赖。全局禁用插件时不启动这个 worker。

<a id="task_scheduling"></a>
## 定时任务

Manager 持有单实例 `TaskScheduler`，按 manifest 的五段 cron 或 `@every` 表达式计算下一次执行，时区为宿主 `time.Local`。启动、重新启用和变更后的任务都从未来时间开始，不补跑停机期间的执行。到点先推进下一次时间，再取得普通进程租约；进程不可用、租约失败或版本不匹配时跳过并记录警告。

同一插件的同名任务共享在途标记，修改声明不会清除该标记。到点时上一次调用仍未返回，就跳过本轮。超时使用 manifest 的 `timeoutSeconds`；宿主 RPC 返回后才归还租约和调度标记。SDK 还按名称跟踪作者回调的实际返回，避免 gRPC 已超时但作者仍在执行时接受同名任务；这类忽略取消的回调也会让 SDK 健康检查失败。

禁用、重启和卸载先暂停后续调度并取消当前调用，再排空进程。暂停保留最近结果，成功卸载清除内存任务记录；宿主重启后结果也会清空。管理接口返回任务名、下一次时间、是否执行中，以及最近一次实际执行的版本、计划时间、开始时间、耗时和错误。错误文本最多保留 1024 字节；跳过的轮次不覆盖已有执行结果。

<a id="development_mode"></a>
## 开发目录

只有 `plugins.enabled` 和 `plugins.dev_mode` 同时开启，`dev_dirs` 才会被读取。开发源将有效目录转换成内存安装记录，交给普通管理器处理；纯静态包不占用进程名额。开发声明不能覆盖已有的数据库安装记录，重复或无效目录分别记录错误，不阻止普通 HTTP 服务启动。

开发记录默认启用、授予声明的全部权限、使用默认额度和配置，并跳过二进制摘要校验。配置更改只保留在内存；重启操作重新读取目录，按新 schema 保留兼容配置。宿主重启重新加载初始开发记录。开发目录由作者拥有，卸载只删除宿主管理目录。配置来源和环境变量见[进程配置](../interfaces/configuration.md#configuration_sources)。
