<a id="single_instance"></a>
## 单实例前提与信任模型

插件系统遵循项目的单实例部署约定：一个后端进程和一个前端实例，宿主前后端整体升级。进程管理、运行状态、回调限流和开发目录加载由该后端持有，不通过 Redis 协调。

插件是管理员信任的代码。独立进程用于隔离崩溃和卡死，不构成文件、网络或操作系统用户沙箱。宿主不继承整份环境变量，也不向插件提供数据库凭据，但同用户运行的恶意代码仍可能读取宿主用户可访问的数据。`GOMEMLIMIT` 只是软限制，RSS 超限会记录告警，硬限制由部署层负责。

<a id="process_lifecycle"></a>
## 进程生命周期

`plugin/provider.Processes` 持有每个插件的监管器，构造时不启动进程。管理调用创建监管循环后，依次完成以下步骤，就绪后才允许获取租约：

1. 校验二进制摘要。
2. 完成 `go-plugin` gRPC 握手。
3. 建立 AutoMTLS 回调通道。
4. 调用 `Init`。

关闭与重启参数如下：

| 阶段或机制 | 规则与参数 |
| --- | --- |
| 正常关闭 | 进入 `draining` 拒绝新租约，最多等 10 秒排空，再调用最多 5 秒 `Shutdown`，最后终止进程 |
| 应用停止 hook | `PluginRuntime` 启动顺序 976、停止阶段 27，总预算 8 秒（更早的 HTTP 阶段已排空请求）；到期取消子进程，不等待插件配合 |
| 健康检查与采样 | 每 15 秒健康检查（单次超时 3 秒），每秒检查退出，每 30 秒采样 RSS 和 CPU |
| 重启与退避 | 进程退出或连续 3 次健康检查失败触发重启；默认退避 1、2、4、8、16、32、60 秒，之后保持 60 秒 |
| Crashloop | 10 分钟内第 5 次异常退出进入 `crashloop`，等待管理员重启、版本替换或禁用后重新启用 |

跨平台清理与隔离约定：

- 进程组终止：Linux 和 macOS 使用独立进程组，取消时先终止同组后代，Linux 另设 `Pdeathsig=SIGKILL`；Windows 保留直接子进程终止。
- 管道读端关闭：强制关闭时，各平台均主动关闭 stdout/stderr 的宿主读端，避免后代继承管道导致传输清理无限等待。
- 父进程看门狗：SDK 每 2 秒检查父进程。Unix 检查父 PID 是否变化，Windows 持有原父进程同步句柄并检查退出状态，避免父 PID 保留或复用造成孤儿进程。
- Socket 目录：Unix socket 使用宿主创建的短临时目录，防止较长数据目录超平台路径限制；目录随该代进程清理，启动失败也删除。插件 `HOME`、`TMPDIR` 仍在该插件的 state 目录内。

<a id="leases_and_callbacks"></a>
## 租约与宿主回调

- 请求租约：`Runtime.Acquire` 不等待启动或容量；不可用、正在排空和超过 32 个在途租约分别返回对应错误。每个租约固定连接代次和版本，归还只执行一次，旧进程退出后才完成的请求不改变新进程租约计数。
- 回调跟踪与排空：每个进程代次单独跟踪宿主回调（插件后台 goroutine 也可发起回调）。停止和异常重启会关闭回调准入、取消剩余调用，并等待处理器实际返回；收到取消信号不等于数据库操作已结束。管理请求超时返回失败，清理继续等待，重试仅在这些调用结束后才能成功。卸载在此之后事务删除安装记录和可选 KV，避免排空期间回写已清除数据。
- 回调鉴权与限流：宿主回调服务绑定安装时授予的权限，不从插件请求获取权限集合。已知无需权限的方法、受限方法和未知方法分开处理，未知方法拒绝执行。回调总量使用每插件每秒 100 次、突发 200 的令牌桶。钱包、兑换码、直接订阅、邮件、验证码、KV 和只读能力均经已绑定的宿主服务执行。
- 审计与日志：写调用审计覆盖权限、限流、排空拒绝和成功重放，记录插件版本及可验证的调用用户，不保存 grant 或配置内容。插件日志转入宿主 `slog`（带插件 ID、版本），每行最多 4 KiB，每插件限速 200 行/秒，内存保留最近 500 行（跨重启保留诊断，不入库）；监管循环汇总丢弃数量。

<a id="http_contributions"></a>
## HTTP 贡献与资产边界

`plugin/httpapi` 复用宿主的 JWT、管理员认证、Backend 模式门禁、面板限流、安全客户端地址和请求语言解析；HTTP 层不自行解析 JWT，gRPC 消息和错误细节留在 `plugin/provider`。

- 路由匹配与鉴权：代理先匹配不可变 manifest，再执行对应认证链；公开 API 和静态资源显式使用公网 IP 限流。
- 跨更新一致性：路由选择与取得进程租约可能跨越版本更新，代理同时核对租约版本和当前 manifest 摘要，再按原选中路由执行。
- 禁用与卸载可见性：卸载和禁用通过普通租约排空；禁用意图提交后立即更新内存可见性，即使排空失败，UI 描述也不再把安装标为启用。
- 静态资源读取：只访问已接受的本地文件元数据，不触发包恢复下载；`os.Root` 限制文件解析范围，固定长度 reader 防止打开后文件增长扩大响应。
- UI 发现：仅检查脚本和样式的存在及尺寸，浏览器按 SRI 校验内容；可选菜单 SVG 限量读取后交给前端净化。接口细节与允许的 MIME 见[HTTP 贡献与公开资源](../interfaces/plugin_contracts.md#http_contributions)。

<a id="frontend_host"></a>
## 前端宿主

宿主与插件共享同一个 Vue 运行时。插件代码仍是管理员信任的浏览器代码，`HostApi` 的接口范围不构成 DOM 或存储沙箱。

- 资源加载：加载器先等待全部样式成功，再插入携带 `data-plugin-id` 和 SRI 的 IIFE 脚本，注册须发生在脚本同步执行期间。加载键包含版本、URL 和完整性摘要，资源请求也附带摘要参数，允许同版本修复绕过旧 immutable 缓存。失败或超时释放本次资源，替换成功后才移除旧样式。
- 发现隔离与容错：UI 描述按登录账号、角色和语言隔离，在途读受代次保护，旧账号响应不能重新发布菜单。全局禁用清空贡献，其余读取失败保留同范围旧菜单供恢复。页面匹配精确 audience 与 manifest 路径；脚本加载失败会刷新一次描述再重试一次，最终错误和组件异常只替换内容区、保留导航外壳。路由或发现结果变化后，旧加载结果不能覆盖新页面。
- `HostApi` 范围：请求限定在当前插件命名空间，保留插件自有 JSON 数据并继续使用宿主会话刷新；导航只允许进入当前插件、当前 audience 已声明页面；用户字段仅含 ID、用户名和角色；页面销毁或账号身份变化后拒绝新请求；每个挂载只保留一个确认问题，替换和销毁均按取消处理。
- 组件适配：SDK 控件复用宿主原生实现，对话框 Teleport 面板携带插件样式作用域。页面支持 Vue 对象组件、函数式组件或返回 Promise 的加载函数；宿主与开发 mock 使用相同适配器，由 Vue 在渲染上下文中调用，同步结果保留响应式跟踪，Promise 交给带超时的异步组件并复用首次结果。
- 验证码组件：按站点配置选用原提供商组件；确认未启用时发空票据，读取失败或配置不全提供重试，腾讯票据保留 `ticket` 与 `randstr`。
- 主题色约定：主题变量引用现有按钮、卡片、输入和状态色。`--tr-color-brand` 对应主按钮填充色 `primary-600`；链接、选中页签和选择标记用 `--tr-color-accent`（浅色 `primary-600`，深色 `primary-500`）。兼容无 accent 变量的宿主时，按响应式 `host.theme` 选同组标准色，不把按钮填充色作深色文字色。

<a id="installation_state"></a>
## 安装记录与本地文件

迁移 305 创建索引源、安装记录、KV 和台账表，`plugin/postgres` 通过共享 Ent 连接执行手写 SQL 并参与上下文事务。安装记录保存当前及上一版本的完整快照（来源、原始 manifest 摘要、平台包、配置、密文密钥、已确认权限和网关版本检查例外）；额度属于安装记录，不随版本交换。

- 启动同步与锁：`Manager` 启动时异步按插件 ID 调用 `Sync`，先完成开发源身份登记，防止管理安装与开发目录发布同 ID 记录。管理用例写库前取得单插件锁并持有到本地调整结束，不同插件可并行处理。已发布快照供请求读取，进程容量由共享锁预留，开发和持久化安装共用 `max_running`。单个安装失败保留记录及错误，不影响其他安装启动。
- 上传与安装：上传预览限制归档大小并校验内容，返回有效期 30 分钟的 token。安装依次检查兼容性、全部权限确认和配置，再校验、解压并发布本地文件，最后保存安装记录。缺必填配置时保存为禁用；保存成功后进程启动失败仍返回安装结果及错误状态。`staging` 在重建包存储时清空，过期上传每 10 分钟清理。
- 本地目录与摘要：`installed/<id>/sha256-<archive-digest>` 绑定归档、manifest、二进制摘要及资产 SRI，同版本不同构建独立存放，强制覆盖不改写回滚包。旧 `installed/<id>/<version>` 目录继续按已接受摘要读取，不再被当前或上一包引用后清理。
- 完整性复核：安装与恢复时核对全部保留文件内容摘要（长度不变的损坏也拒绝复用）；普通资产读取仍只查元数据与读取边界。
- 缺失包恢复：索引来源本地文件缺失或损坏时按已接受 URL 和摘要重下（仅 HTTPS，限制重定向、大小和时间；GitHub 下载前缀只适用于声明的两个 GitHub 主机）。上传来源返回 `PLUGIN_PACKAGE_MISSING`，由管理员重传相同 ID、版本和 manifest 摘要的包修复；修复先排空旧进程，保留配置、权限、额度及 KV，再发布新文件身份。
- 卸载：先关闭请求准入并排空宿主回调，再在同一事务删除安装记录及可选 KV，最后删除管理目录。排空失败保留安装记录，文件清理失败可重试。台账始终保留，以便后续继续识别已执行的幂等键。
- 管理页面：`/admin/plugins` 启停插件，`/admin/plugins/:pluginId` 查看状态、采样资源、配置、额度、日志和版本，`/admin/plugins/sources` 管理索引来源；操作复用 TOTP step-up。全局关闭时保留查看与卸载入口，执行和新安装控件不可用。
- 管理端状态展示：上传先展示未执行包预览，再确认完整权限安装；需要配置与进程启动失败分开呈现，不用「已安装」替代「运行中」。

<a id="catalog_updates"></a>
## 索引与更新

`CatalogService` 由 `PluginCatalog` hook 在启动顺序 974 登记，先确保内置来源再开放管理接口。内置记录 ID 和管理员启用选择跨重启保留，配置 URL 变化时清旧缓存；自定义来源可设 Ed25519 公钥，改 URL 或公钥同样清旧缓存。

删除来源只解除安装记录当前及上一版本索引外键，保留已接受的包地址与摘要。安装快照保存与来源删除经数据库行锁协调，保存旧快照时已删除来源保持空关联，避免更新失败恢复写回失效外键或丢失旧版本。

- 索引拉取与验签：`provider.IndexClient` 经下载代理读 HTTPS 索引和相邻 `.sig`，总预算 20 秒，文档上限 8 MiB。内置来源须经 `OfficialIndexKeys` 验签（内嵌官方公钥，私钥在官方索引仓库 `INDEX_SIGNING_KEY` secret，空公钥集合拒绝内置验签）。
- 自定义来源验签：固定公钥须匹配；无公钥自定义来源仅在签名文件不存在时按 `unsigned` 接受。签名无效、传输失败或 schema 无效均保留旧缓存。
- 缓存与刷新：首次读取等待无缓存来源；超过 1 小时的有效缓存先返回再后台刷新。同来源共享在途刷新，单个等待者取消不终止其他等待者。来源修改、删除和缓存发布共用来源锁；停止时封闭准入、取消刷新并等待实际返回。`signature_status` 记录最近验签观察，`cached_at` 为最后接受文档时间，失败状态可与仍可用旧缓存并存。
- 市场条目与版本策略：条目以索引 ID 和插件 ID 联合标识。普通安装拒绝同 ID 其他来源；强制覆盖时安装接口可切换来源，更新接口仍固定当前索引。推荐版本为最高兼容、未撤回稳定版，预发布版可在详情显式选择。已安装来源的下架条目和当前版本撤回原因仍可查看；安装列表只读缓存注释，不让状态轮询等待网络。较新 manifest 先查最低宿主版本再决定是否严格解析，未来贡献显示不兼容而不拖垮来源。
- 更新与强制覆盖：两者共用替换流程，先验目标包再保存新当前快照和完整上一包。强制覆盖保留启用状态、额度、KV 和台账，允许同版本不同归档。配置按目标 schema 迁移，普通与 secret 互换不继承原值，启用插件要求迁移完整。
- 版本例外：忽略版本检查仅排除 `HOST_TOO_OLD` 和 `HOST_TOO_NEW`，完整 manifest 仍须通过当前宿主严格解析；该决定随快照保存，新一次替换默认重检。
- 失败自动恢复：新版本就绪前保留原当前和上一版本目录；启动失败或 30 秒内未就绪时，以独立恢复预算写回原完整安装记录并重启旧版本，失败响应含新版本错误、最多 50 行日志及恢复结果（禁用安装只更新记录和文件）。
- 手动回滚：交换完整快照，额度和启用选择不变；被恢复的上传包丢失时保留在该版本失败状态，可重传同版本和 manifest 摘要修复。就绪后仅保留当前和上一版本目录，失败更新不丢失原回滚目标。

<a id="configuration_secrets"></a>
## 配置与密钥

配置经 manifest schema 校验后，普通值和 secret 分开保存。secret 使用应用共享 AES-GCM 加密器，保存非空密钥要求固定的 `security.secret_encryption_key`。GET 仅返回 `{set: true|false}`；PUT 省略保持旧值，空字符串清除。禁用安装可保存未填完整的配置，启用前须通过完整校验。

- 运行时通知：配置保存后通知运行中插件；配置通知不受普通请求容量上限阻挡，仍计入该代进程在途数和排空等待。监管器记录期望配置，各代记录成功应用的配置，通知失败不跳过后续相同值重试；启动期间修改配置会替换旧代，避免旧 `Init` 输入覆盖新意图；未改值的协调保留原有 backoff 或 crashloop 状态。未实现 `ConfigChanged` 时重启，回调失败保留已保存配置并记警告。
- 迁移与审计：版本配置迁移保留旧快照，禁止将旧 secret 自动搬入新普通字段。配置写入审计正文和 MCP 确认预览整体隐藏动态值，不依赖插件作者选定的密钥名称。
- 管理端草稿隔离：配置页按插件 ID、版本和 manifest 摘要隔离编辑状态。更新或回滚后丢弃旧草稿并重读配置与密钥存在标记，旧读取、保存结果和待确认 step-up 不能覆盖新页面状态；普通进程状态轮询保留当前草稿。

<a id="write_capabilities"></a>
## 写能力与余额台账

`Grants` 从持久 JWT secret 派生专用 HMAC 密钥，票据绑定插件、用户和 5 分钟有效期，重启后同密钥仍可验证未过期票据。钱包扣款须持有效本人票据；加款可面向任意已有用户，附带有效票据仅用于审计调用者。

### 钱包余额调整

1. 校验权限和参数后，进入 PostgreSQL 插件级 advisory transaction lock。
2. 检查幂等键（同插件跨能力共享）：已存在键先比较规范化业务内容（金额按 8 位小数整数单位规范化，临时 grant 不参与比较，更新票据后可重放同一扣款），再返回原结果。幂等重放先于额度检查，后续调低额度不改变已提交结果。
3. 新操作在同一事务内读取安装额度、计算宿主时区自然日统计（时点在取得锁后确定并同时用于记录，跨午夜不混用两天）、调用 `BalanceStore.AdjustBalance` 并写入 `plugin_ledger`；任一步失败全部回滚。加款不增加 `total_recharged`，不触发直接充值返利；余额调整沿用非负约束。
4. 事务提交后使用独立 5 秒预算清除用户认证缓存、余额缓存，并经 `RecordAdjustment` 写入 `plugin_balance` 历史（失败仅记诊断，重放不重复写历史）。

台账是资金效果的权威记录。用户及管理员余额历史显示插件来源和 `[<pluginId>] <reason>`，普通兑换码内部备注继续隐藏。

### 直接订阅发放（`subscription.grant`）

同时检查安装额度中的套餐白名单（默认空，未配置不可发）、单次天数、单用户每日次数和总次数。发放复用 `AssignOrExtendSubscription` 的当前套餐额度、有效期规范化和排队规则，`AssignedBy` 与 `SourceOrderID` 留空。先按未删除条件锁定用户行，再在同一台账事务内发放，提交后清除用户认证缓存。

### 邮件发送（`notify.email`）

- 认领与额度：同一台账先提交 `pending` 认领与额度，再调通知服务。所有认领均计入每日次数（含退订、无邮箱、失败和结果不明）。同键并发调用等待原调用返回并保存结果，等待取消不改变原认领。
- 结果记录：完成记 `completed`（成功与跳过分别保存 `delivered=true/false`）；发送前错误记 `failed` 并同键重放原错误；SMTP 调用后失败、重启遗留认领或最终结果写库失败返回 `EMAIL_DELIVERY_UNKNOWN`，不自动重发。结果写库使用独立 5 秒预算；通知成功标记失败但 SMTP 已确认时，仍在插件台账保存已送达。
- 幂等键隔离：邮件幂等键按原始字节区分大小写与标点。通知层投递标记使用独立命名空间和原始键 SHA-256 摘要，避免通知键规范化合并不同操作。旧台账决定已认领操作是否重放或结果不明；新认领不读取旧的、可能碰撞的通知标记。

### 兑换码签发（`redeem.issue`）

仅允许余额、并发和订阅类型，固定单次使用且不要求付款历史。码值由持久 HMAC 密钥、插件 ID 和幂等键确定。额度检查、普通兑换码创建与台账插入在同一 Ent 事务中执行，失败一起回滚；创建本身不改变用户权益。

订阅码默认天数在重放判断之后、事务之内解析校验，保存至可空的 `redeem_codes.validity_days`。请求中的 `0` 保留在幂等意图，实际天数另存台账结果，套餐改长不增加已发码权益也不影响原请求重放。订阅码台账 `amount` 为 0，余额码和并发码记各自面值；普通兑换继续走原入口（含余额码累计充值与返利）。

<a id="read_capabilities"></a>
## 只读能力与字段范围

`Queries` 在调用业务读取器前检查权限、用户 ID、批量数量和时间范围。

- 用户与身份：`user.read` 与 `wallet.read` 分开授权，用户邮箱另需 `user.email`，精确邮箱查找同时需 `user.lookup` 和 `user.email`。身份绑定只返回第三方记录及标准化 `username`、`display_name` 元数据，不返回本地邮箱身份或任意上游 claims。
- 用户精确查找：经 identity 核心走专用 SQL，按 ID、用户名或邮箱三选一。用户名按原值相等，邮箱按 `LOWER` 相等，百分号等不作为通配符；排除已删除账号；按 ID 最多返回 100 条资料并直接连接头像记录，不进入管理员备注与 API Key 搜索。
- 用量范围：`usage.self` 需匹配当前插件和目标用户的有效 grant，`usage.read` 可读任意目标。批量查询最多 100 个 ID，统计范围不超 93 天，排行最多 100 行。
- 用量口径与排行：费用取实际用户扣费值：`summary` 保留用户仪表板本人及当前拥有团队口径；`batch` 沿用按调用人统计费用入口并补同时间范围请求与 token 计数（含零费用记录）。排行保留公开名字遮罩，网站排行开关不限插件权限。
- 订单、模型与分组：订单每页最多 50 条，仅映射协议声明字段；`amount` 保留原订单数量或价格含义，不代表支付通道实付金额，也不统一换算 USD；充值资格判断使用钱包累计充值字段。模型目录复用公开端点 DTO 和成功 envelope；可用分组复用原权限筛选及用户倍率覆盖（含显式零倍率）。

<a id="kv_storage"></a>
## KV 存储与维护

- 隔离与并发控制：KV 命名空间取自进程绑定，RPC 只能指定 `collection` 和 `key`。写入在完整键身份的 advisory transaction lock 下检查版本并对现有行加行锁；替换用条件 UPSERT，自增用同一条语句更新值和版本。过期数据在读取和条件判断中视为不存在，但物理行未清理前新写入继续递增原版本；清理跳过被锁定行，避免版本检查与替换之间删掉记录。
- 软配额采样：按物理行统计，每插件最多 50000 个键、64 MiB（JSONB 文本与 key 字节）。单个后台 worker 启动后立即采样，之后每 5 分钟采样；失败保留上次完整结果，首次成功前允许新增。达任一上限拒绝新增逻辑键，未过期已有键可改可删；过期行清理前仍占统计额度，过期键复用按新增判断。
- 过期清理与启停：同一 worker 每 10 分钟清理过期数据，每批最多 1000 行，单轮预算 30 秒，每批独立提交（取消或错误不恢复已删批次）。`PluginKV` 在启动顺序 975 登记（早于插件进程协调），关闭与进程同处阶段 27 并等待后台操作返回后释放数据库依赖。全局禁用插件时不启动该 worker。

<a id="task_scheduling"></a>
## 定时任务

- 调度策略：`Manager` 持有单实例 `TaskScheduler`，按 manifest 五段 cron 或 `@every` 表达式在宿主 `time.Local` 计算下一次执行。启动、重新启用和变更后的任务从未来时间开始，不补跑停机期间的执行。到点先推进下一次时间，再取普通进程租约；进程不可用、租约失败或版本不匹配时跳过并记警告。
- 防重入与超时：同插件同名任务共享在途标记，修改声明不清除该标记；到点若上次调用仍未返回则跳过本轮。超时取 manifest `timeoutSeconds`，宿主 RPC 返回后才归还租约和调度标记。SDK 按名称跟踪作者回调的实际返回，防止 gRPC 超时但回调仍执行时接收同名任务；忽略取消的回调也会使 SDK 健康检查失败。
- 暂停、卸载与状态：禁用、重启和卸载先暂停后续调度并取消当前调用，再排空进程。暂停保留最近结果，成功卸载清除内存任务记录，宿主重启也会清空。管理接口返回任务名、下一次时间、是否执行中，以及最近一次实际执行的版本、计划时间、开始时间、耗时和错误（错误文本最多 1024 字节；跳过轮次不覆盖已有结果）。

<a id="development_mode"></a>
## 开发目录

仅当 `plugins.enabled` 和 `plugins.dev_mode` 同时开启时才读取 `dev_dirs`。开发源将有效目录转换为内存安装记录交给普通管理器处理，纯静态包不占用进程名额。开发声明不能覆盖已有数据库安装记录；重复或无效目录分别记录错误，不阻止普通 HTTP 服务启动。

开发记录默认启用、授予声明的全部权限、使用默认额度和配置，并跳过二进制摘要校验。配置修改只留在内存；重启操作重新读取目录，按新 schema 保留兼容配置；宿主重启重新加载初始开发记录。开发目录由作者拥有，卸载只删除宿主管理目录。配置来源和环境变量见[进程配置](../interfaces/configuration.md#configuration_sources)。
