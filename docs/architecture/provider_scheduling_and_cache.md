## 调度输入

调度接收请求的分组、强制平台、客户端模型、映射后模型、endpoint 与媒体意图、协议 transport、OAuth 与 privacy 要求，以及可选的 session 标识。

- 优先级唯一来源：`providers.priority`。`provider_groups` 仅记录成员关系，没有分组内独立优先级。
- 候选桶划分：平台为空的 `single` bucket 包含 11 类平台的全部组内提供商，供普通请求读取平台无关快照；指定平台的 bucket 用于专用入口或明确能力选择。
- 强制平台过滤：`/antigravity/*` 等专用入口叠加平台过滤，分组成员、模型和协议门禁照常执行。
- 分组范围边界：所有请求均限定在当前分组内，未关联分组的提供商不进入候选池。
- 多分组归属：同一提供商可属于多个分组，各 bucket 独立计算资格和模型范围，全局优先级保持一致；分组查询按 `providers.priority` 和 `provider_id` 稳定排序。

## 调度器模式

### 模式选择

`groups.scheduler_type` 控制分组级调度策略，取值为 `basic` 或 `advanced`，新建和历史未配置分组默认为 `basic`。该字段与平台能力无关；未绑定分组的请求无法选出提供商。

- 分组回退边界：Claude Code-only、分组不可用等回退由入口完成，入口重检目标分组权限、资金和协议，并更新有效 Key、分组快照和 `RoutePlan`。
- 严格归属校验：选择器只接受已准入分组，分组 ID 与上下文或 `RoutePlan` 不一致时直接拒绝，选号过程不会跳转回退分组。
- 最终分组生效：回退结束后按最终分组读取 `scheduler_type`；强制平台仅缩小平台范围，最终分组的高级模式和参数覆盖继续生效。

### 参数合并

高级调度参数按三层优先级逐字段合并，规则校验与合并由 `internal/scheduler/policy` 实现，生产选号与管理端诊断复用同一份有效参数和运行态统计，凭据留在调度核心之外。

| 优先级 | 来源 | 生效与缓存规则 |
| --- | --- | --- |
| 1（最低） | `scheduling.advanced` | 进程级默认值 |
| 2 | `advanced_scheduler_*` | 网关运行时设置，短 TTL 缓存 + singleflight，保存后立即刷新 |
| 3（最高） | `groups.advanced_scheduler_overrides` | 分组覆盖 JSON；缺失字段继承，显式 `false` 与 `0` 生效，`{}` 全部继承 |

参数约束和边界规则：

- EWMA 与逃逸配置：错误率和 TTFT 两个 EWMA alpha 范围均为 `0 < alpha <= 1`；sticky escape 的开关、TTFT 阈值和错误率阈值按相同三层优先级合并。
- 反馈归属稳定：运行时反馈按提供商共享，但请求完成时按该请求最终分组解析出的 alpha 回写，途中修改配置不会导致选择与反馈错配。
- 全零权重合法：7 项基础权重全为 0 仍合法，粘性加成继续生效；完全并列的候选按 `providers.priority` 和 `provider_id` 稳定决胜后再做 Top-K 抽样（负载和等待已计入评分信号，同分仅此一条规则）。
- 数值溢出保护：合并后的基础权重之和与完整权重之和均须为有限数，管理端拒绝溢出写入；请求时遇历史异常对象回退至已验证全局值，避免 `NaN` 或 `Inf`。
- 基础模式隔离：基础分组和无分组路径忽略 `advanced_scheduler_overrides`，残留配置不影响基础调度。

### 高级调度流程

基础调度按优先级、最近使用、负载、粘性和等待选择提供商，与高级调度互不影响。高级调度在硬过滤完成后接管排序：

1. 硬过滤：检查分组、强制平台、模型、能力、提供商状态、限流、代理、privacy、配额、窗口费用和 RPM。
2. 评分与抽样：综合优先级、负载、队列、错误率 EWMA、TTFT EWMA、窗口重置和可选会话粘性打分，在 Top-K 内做加权无放回抽样。
3. 满槽与缺测处理：暂时满槽或负载率 100% 且硬资格合格的提供商照常进入评分，选定前逐个复核并发槽，全部满槽时生成等待计划（无槽探测忽略占用）。无反馈样本时错误率按 0% 计算；负载快照、TTFT、窗口或平台专属额度缺失时使用中性值。
4. 统计回写与复核：高级调度选出的请求，其结果、失败、TTFT 和切换回写运行时统计；流开始后不切换。补全凭据和数据库复核时重检分组成员、模型和协议，复核得到的完整记录为准，不被旧快照覆盖。

### 平台差异与粘性加权

| 平台 | 调度补充规则 |
| --- | --- |
| 跨平台文本 | 同组全部平台参与，按实际提供商应用协议、模型、订阅优先和传输限制 |
| Anthropic | 检查窗口费用、RPM、会话上限和配额门禁 |
| Gemini | 复用本地配额预检 |
| Grok | 检查免费层、团队模型冷却和媒体资格 |
| Antigravity | 按模型和协议能力直接参与调度，无需额外混合开关 |

粘性与展示规则：

- 硬粘性与逃逸：关闭粘性加权时，已有硬会话粘性照常生效。OpenAI previous response 不能跨提供商时无论开关均硬绑定，可跨提供商时才作加权信号；非 OpenAI 平台无此绑定，诊断标为 `ignored`。共享错误率或 TTFT 超过逃逸阈值时，仅当前请求逃逸，原绑定保留。
- 粘性加权语义：开启粘性加权时，会话或上一响应所在提供商仅获评分加成，与其余 Top-K 候选一起按权重抽样，不强制排首位，Top-K 全败后无保底尝试。window-cost 和 RPM 的 sticky-only 区间仍允许原绑定提供商进入评分。
- 管理端评分预览：仅对高级分组显示，与生产使用同一评分函数、运行状态和不含凭据的候选输入；Codex 额度余量的 8 小时有效期和次窗口折扣由 provider 模块计算。预览分仅供参考，实际命中仍取决于请求时硬过滤。

### Codex 自动审查的父线程

Codex 自动审查请求与父线程的关联，仅在同时满足三项条件时建立：模型为 `codex-auto-review`；Header 或 metadata 含不冲突的 `guardian` 或 `review` 声明；带有父线程 ID。

- 关联查询限定在当前分组的粘性命名空间内，子请求不能覆盖父线程绑定。
- 新旧两种会话散列从同一种子派生并随本次请求传递。
- 普通模型、线索缺失或声明冲突时不建立关联；该关联不代表任何身份授权。

### 短暂失败与选择适配

提供商与模型的短暂失败状态由进程内共享的 `ModelTransientState` 持有（模型名先按平台规范化），进程重启后清空：

| 连续失败次数 | 处理行为 |
| --- | --- |
| 第 1 次 | 仅计数，不冷却 |
| 第 2 次 | 冷却 10 秒 |
| 第 3 次及以上 | 冷却 45 秒 |
| 任意成功 1 次 | 计数清零 |

短暂失败状态保留 30 分钟并受容量上限保护。选择适配层的状态边界如下：

- 凭据隔离：完整记录在 Redis 读取侧解码，评分和排序仅接收不含凭据的数据，仅受控执行目标携带凭据。
- 记录版本隔离：单次选择维护独立关联表，同一 ID 的快照记录、fresh 记录和数据库复核记录互不覆盖；普通 Grok 免费层与高级选择各自维护缓存范围。
- 共享资格与提示快照：跨平台文本与固定提供商 WS 复核共用兼容资格与协议能力判断。配额阈值、分组隐私要求和单次代理隔离绕过标记随请求值快照传递，派生 attempt 仅修改自身副本，单次 fail-open 标记不跨请求生效。

## 评分诊断

管理员可通过高级调度评分诊断查看当前候选池的实时解释，计算始终在核心之外保留凭据。

| 诊断模式 | 允许输入 | 限制 |
| --- | --- | --- |
| 基准诊断 | 分组 | 不指定模型、会话粘性和上一响应粘性 |
| 模拟诊断 | 分组、模型、两个提供商 ID | 禁止传入 session hash、previous response 内容、凭据或代理认证信息 |

诊断范围与只读保证：

- 检查项覆盖：使用不分页的分组全集统计排除原因，复用分组 OAuth-only 与协议准入、模型映射与白名单、模型运行时封禁、API Key/Bedrock 额度、窗口费用、RPM、只读自动停调阈值、代理流隔离、OpenAI/Grok 配额自动暂停、Grok 团队冷却与免费层缓存、影子母提供商健康及分组上游白名单。
- 严格只读：不拿并发槽、不注册会话、不写粘性、不持久化停调、不启动后台配额刷新，也不修改运行时统计。
- 未评估信号：依赖请求输入的门禁（endpoint、transport、Compact、媒体）返回 `not_evaluated`，实际请求在完整上下文中补检。
- Spark 影子资格：调度、诊断与 WS 复核共用 `ParentHealthyForShadow` 规则，要求母提供商存在、仍为 OpenAI OAuth，且凭据未因状态、到期或临时停调失效；母提供商全局限流、过载和手动调度开关不影响影子。Spark 影子默认模型表由 OpenAI Codex 别名表生成独立恒等映射。

单次候选池的评分公式：

- `base_score = Σ(weight_i × normalized_i)`
- `final_score = base_score + sticky_bonus`
- `selection_weight = final_score - top_k_min_score + 1`
- `selection_probability = selection_weight / top_k_weight_sum`

特殊模式与 EWMA 展示规则：

- 订阅优先与硬粘性：开启订阅优先且存在可用 ChatGPT 订阅提供商时，仅按订阅池计算排名、Top-K 和概率，普通提供商标 `deferred`；订阅池无可用时回落普通池。
- 粘性模式展示：开启粘性加权时诊断概率即含加成的 Top-K 抽样概率；关闭粘性加权且硬粘性可用时，保留原排名和 `in_top_k`，选择模式标 `sticky_forced_first`（命中者概率为 1，其余为 0）。发生粘性逃逸时，原绑定提供商按普通候选执行 window-cost 与 RPM 门禁，逃逸与未评估门禁作为独立策略信号展示。
- EWMA 基线与缺测：TTFT 实测 `0ms` 参与延迟范围归一化，未观测或全部已知样本相等时使用中性值。错误率初始基线为 0%（无样本健康度为 1），首次失败即从零基线更新 EWMA，健康度立即低于未观测提供商，聚合值保存样本数和最近观测时间。
- 缺测文案与参数来源：诊断将未观测错误率标为"0%（未观测）"，缺失的负载、TTFT、窗口重置或平台额度标为"未观测，使用中性值"且仍可调度。负载分母取 `EffectiveLoadFactor()`；参数逐字段标明来源（分组覆盖、全局运行时设置或进程默认值）。
- 模型缺失诊断：直接读取持久配置的提供商池（忽略临时限流、过载和停调），复核分组、协议路线和模型范围，不以调度快照为空断定模型不存在。查询限定当前分组，无分组时不读池；未解析模型按 `PricingConfigService.ResolveRoutingModel` 解析。
- 兼容路由一致性：OpenAI 兼容选择、诊断和 WS 复核共用 `ModelPolicy.SupportsCompatibleRouting`，透传提供商同样遵守白名单、映射（含 `effort_model_mapping`，随精简调度元数据进入快照，规则见[提供商组合映射](../domains/routing_and_billing.md#provider_effort_model_mapping)）和默认模型目录。

## 快照一致性

本节与[认证快照](#认证快照)共同作为当前调度与认证缓存版本及键前缀的单一来源。

| 缓存对象 | 命名空间 / 版本 | 关键说明 |
| --- | --- | --- |
| 调度快照与状态 | `sched:v6:` | 包含 buckets、outbox watermark、provider、meta、last_used、active、ready、ver、epoch、retired、group lifecycle lock |
| Bucket 重建锁 | `sched:v4:lock:` | 随机 owner token 校验释放，防止旧持有者误删继任者锁；key、类型和 TTL 跨版本不变 |
| API Key 认证缓存 | 版本 `48`（`KeyApiKeyAuthSnapshotVersion`） | 含准入集合、转换映射、Responses 图片策略、分组价卡和 Fast 策略，见[认证快照](#认证快照) |

### 轻量快照与字段约束

编码器区分 `nil` 与空集合，完整快照与轻量快照共享以下字段边界：

- 通用字段与脱敏：完整与轻量快照均保留 `upstream_protocols`、认证方式、`responses_ws_connection_mode`、代理关联 ID、Coding Plan 监控身份摘要，以及 OpenCode 模式、已接受目录和人工模型协议覆盖。
- 凭据边界：轻量快照保留 `api_key` 与非敏感策略字段，排除 OAuth、会话和云签名密钥；调度核心仅读无凭据数据，执行凭据由 provider 模块受控提供。
- 协议过滤时机：评分前按最终映射模型解析原生协议，换号、fresh 复核和数据库复核均重检，自动探针同步检查模型协议启用状态；转发目标只留在本次副本，不污染共享缓存。
- Gemini 轻量字段：配额预检在补全凭据前执行，轻量快照必须保留 `provider_type`、`oauth_type` 和 `tier_id`。第三方提供商跳过本地官方预检，官方按保存等级选配额，缺失字段会退回默认档位。
- 图片能力轻量字段：图片筛选在补全记录前执行，轻量快照必须保留 `base_url` 以区分第三方中继与官方服务；OpenAI 兼容中继中的 Gemini 图片别名靠分组 `reference_model` 继承能力，缺失地址会导致误判。轻量字段通过启动和周期重建自动更新，无需改分组配置。
- Qoder 索引与身份摘要：PostgreSQL 和 Redis 读取 Qoder 记录时为账号模型建只读索引（单次路由复用，账号切换或快照替换后更新）；轻量快照保留站点、账号模型观察和从完整凭据派生的目录身份摘要，无需复制访问令牌即可验证观察身份（完整记录直接从凭据计算）。
- Qoder 目录失效与未同步：账号、组织或站点变化时双端拒绝旧目录，已识别账号轮换访问令牌可继续沿用；目录未同步时，选号拒绝该提供商，诊断视为暂时不可用而非模型不存在。

### 同步、并发保护与回退

`scheduler.SnapshotService` 负责 bucket 快照重建、outbox 消费与受限回退。启动时异步执行初始重建，outbox 立即消费首轮；运行期持续消费调度 outbox，并定期全量重建修复漏掉的通知与外部写入。同一事务内写入的调度事件在提交后尽力发布；状态热更新可先发布快照，再经 outbox 与失效通知传播。

一致性与容错规则：

- 写入栅栏：bucket 写入带 token 和 epoch，较慢的旧重建无法覆盖新状态。
- 退役墓碑：已退役 bucket 写入 tombstone，延迟事件无法重开已删分组。
- 生命周期互斥：分组生命周期 lease 协调 reopen 与 retire，`sched:v4:lock:` 保证同一 bucket 同时仅一个重建。
- 事件分流：提供商变化、分组变化、批量变化、last-used 和全量重建分事件处理，热字段更新仅重算受影响部分。
- 受限数据库回退：快照未就绪或读失败时可有限回退数据库，具备独立超时和 QPS 上限；超限返回 cache-not-ready 或 fallback-limited 错误。配置以数据库为准，热路径快照短暂不一致靠版本栅栏和周期重建收敛。
- 启停边界：重复调用 `Start` 跳过启动和重建；`Stop` 取消周期任务、排队任务和支持 context 的在途操作，在应用剩余预算内等待，停止后不可重启；等待超时时任务与持久 outbox 可能未排空。
- 水位推进限制：消费水位按事件 ID 推进，较小 ID 的事务若在水位越过后才提交，该事件会被跳过并由定期全量重建修复；清理时的 10 秒宽限仅推迟删除，不重新轮询已越过的旧 ID。

## 候选筛选与评分

候选提供商按固定顺序逐层过滤：

1. 分组关联、强制平台、active、schedulable 和提供商有效期。
2. 提供商级、模型级和 endpoint 级的临时不可调度、限流恢复时间及配额状态。
3. 映射后的最终模型、白名单和提供商 capability。
4. OAuth-only、privacy、客户端类型、站点和区域、媒体资格及所需 transport。
5. 当前并发槽与等待策略。

特殊平台与评分边界：

- Bedrock 路由筛选：统一解析型号、来源区域和全局推理开关，找不到核实有效路由的提供商不进入候选；模型目录与持久可用性诊断共用同一规则，见 [Bedrock 模型与来源区域](../interfaces/anthropic_upstream.md#bedrock_region_routing)。
- OpenAI/Grok 扩展信号：硬过滤后才比较优先级、近期使用、负载、排队、错误率、延迟、重置窗口或配额余量。OpenAI 和 Grok 仅在请求需要时补充 Responses transport、WebSocket、旧版 `/responses/compact`、原生 `remote_compaction_v2`、previous response、订阅和额度信号。
- 压缩能力门禁：原生 `remote_compaction_v2` 走普通 Responses 路由，独立读取管理员 `openai_native_compaction_v2_mode`，不受历史探测和旧版 Compact 开关影响。
- 压缩两态与复核：压缩资格只有启用和关闭两态（关闭排除，启用仍须满足普通 Responses 能力），调度元数据保留两种压缩开关和文本路由配置；快照显示关闭时仍允许最终数据库复核（防止管理员重开后因旧快照漏选），数据库确认关闭则不可调度。
- 计费与排序解耦：评分只看调度信号，上游声明倍率、OAuth 参考倍率和 `upstream_cost` 权重不参与排序；提供商本地 `rate_multiplier` 和共享价格配置的上游计费模型来源仅用于结算。新增评分项在硬资格之后生效，缺测按中性值处理。

## 提供商自动停调阈值

运行时设置 `provider_scheduling_thresholds` 接受 1 到 100 的整数（100 表示关闭门禁）。提供商凭据中的 `provider_scheduling_threshold` 可覆盖平台默认值，同样限定 1 到 100（浮点数四舍五入到最近整数）。

| 平台 | 平台默认值 | 评估指标与特殊规则 |
| --- | --- | --- |
| `openai` | 100 | 读身份匹配、未重置、未超陈旧期限的 Codex 5h 和 7d 窗口；`codex_*_used_percent` 按 0-100 百分数解释（`1.0` = 1%）；历史快照缺 `codex_usage_updated_at` 或无法解析时按 fail-closed 生效 |
| `anthropic` | 100 | `utilization` 字段（0-1 比例）换算成百分比 |
| `grok` | 100 | 仅读响应头滚动 quota 窗口，官方 7d/30d 账单周期不参与 |
| `kimi`、`zhipu` | 省略且无提供商覆盖时跳过 | 读 Coding Plan 统一用量快照 `limits` 中的百分比与重置时间 |
| `gemini`、`kiro`、`antigravity` | 不参与 | 即使存在观测字段也不执行此门禁 |

触发与缓存行为：

- 暂停截止计算：多窗口同时达到阈值时，取重置时间最晚的窗口作为截止时间。快照过期、明确陈旧、缺少截止时间、身份不匹配或无观测数据时不暂停。
- 状态落库与广播：命中后写入带结构化来源的临时不可调度原因与截止时间，并触发失效传播（状态未变不重复写入），管理员可区分阈值门禁与普通限流。
- 设置读取缓存：进程内原子缓存 + singleflight；配置项缺失按正常 TTL 缓存默认值，仅数据库故障使用较短错误 TTL；保存后立即替换缓存，部分更新未含该字段时保留原缓存。
- 进程内停调隔离：OpenAI 和 Grok 的进程内停调、同提供商 429 恢复窗口和刷新失败发布版本由共享的 `RuntimeBlockState` 持有。Grok 回滚暂定停调仅撤销本次安装版本，不覆盖后续延长或重新声明的停调；凭据版本阻断无匹配版本时跳过身份散列计算。

## 粘性与等待

手动 session、previous response、WebSocket 或平台内部上下文均可建立粘性。命中粘性的提供商仍须通过当前快照的状态、分组、模型和策略校验；提供商被禁用、移出分组、限流或能力不满足时旧绑定失效。

- 会话与窗口费用缓存：会话注销仅操作调度会话；窗口费用缓存键前缀为 `window_cost:provider:`，TTL 30 秒，共用 Redis。会话批量查询使用支持冷启动的 Lua 调用，Redis 脚本缓存清空后不会将 `NOSCRIPT` 误判为会话不存在。
- Anthropic 会话保留：OAuth 与 Setup Token 提供商的 `max_sessions` 限制空闲窗口内活跃会话数。Messages 正常成功（含流式、换号后成功）或返回可结算部分结果后保留会话注册（按最后活动时间和空闲超时过期），请求结束仅释并发槽；未成功请求和被放弃的 attempt 立即注销会话，防止失败请求占满空闲窗口。
- 粘性溢出与有界等待：粘性提供商并发槽和等待队列均满时，负载感知可让本次请求临时溢出至其他合格提供商，不改写持久粘性绑定。并发满但短期可释放时进入有界等待队列（轮询退避、总截止时间、context 取消），等待后重新选号并丢弃过期结果；无长期合格候选直接报错，不进入等待。

资源租约与释放边界：

| 租约层级 | 持有资源 | 释放与回滚规则 |
| --- | --- | --- |
| 请求租约（`Lease`） | 用户槽、API Key 统计、已确认拿到的等待计数 | 拿到即登记，重复释放幂等；等待计数递增失败照常放行且不递减，不确定计数靠 TTL 清理 |
| 尝试租约（`AttemptLease`） | 提供商槽、串行锁、会话登记 | 补全完整提供商或协议复核失败立即回滚；`Finish` 按成功/可结算部分结果/失败决定是否保留会话（物理槽提前释放与逻辑失败分开处理） |

- 独立资源边界：WS 入站与 Live 租约各自独立；图片本地限流与 Redis 提供商池分开计数；同步 `WaitObserver` 仅通知 HTTP 输出心跳，SSE 格式、Flush 和写失败处理归 HTTP 层。
- Qoder 释放与重试归属：Qoder 已进入上游的流式请求采用完成后释放（客户端断开时停写下游，在预算内收集尾部 usage 后归还槽位）；等待中和非流式请求按各自取消规则处理。实际业务输出开始后的重试由网关执行层判定，scheduler 不维护 failover 循环。

## 失效与恢复

- 触发失效的变更：提供商启停和删除、凭据刷新、分组关系、优先级、模型映射与白名单、代理可用性、限流和临时不可调度、privacy 与可调度资格。
- 桶更新范围：提供商变化同时更新所属分组的平台无关桶和相关平台桶；删除提供商或无法确定原平台时重建受影响分组的全部桶。
- 一致性兜底：数据库写入成功但失效广播失败时记录可操作告警，依靠定期重建恢复；只发通知不落库会在重建后回到旧值。
- Extra 字段合并：原子合并仅保留有效系统状态（如 Ollama Cloud 管理会话和用量快照），凭据或代理变化时按规则保留或清除；所有写入路径直接丢弃历史字段 `upstream_billing_probe` 和 `upstream_billing_probe_enabled`，不触发 CAS、outbox 或调度快照失效。
- 控制面查询隔离：API Key 上游用量查询仅存在浏览器缓存，不写入调度缓存、数据库或提供商 `Extra`，失败不影响转发，且使用独立并发槽，见 [API Key 上游用量查询](../interfaces/upstream_usage.md)。

## 认证快照

### 分组定价快照

API Key 认证缓存版本为 `48`（`KeyApiKeyAuthSnapshotVersion`），快照完整性由版本号判断，与旧媒体字段是否为空无关。

- 策略字段：`RoutingPolicy` 保存独立模型策略与功能策略（准入集合、转换映射、Responses 图片策略、分组手动 Fast 策略、Key 的 `force_claude_1h_cache` 等）。
- 价卡字段：`ModelPricing` 保存完整分组价卡（上下文区间、Fast/Flex、Max 推理和分时规则），价格继承与展示规则见[分组模型价卡与倍率继承](../domains/routing_and_billing.md#group_model_pricing)。
- 分组失效：分组更新事务提交后触发按分组失效，与认证模块的 TTL、jitter、负缓存、发布订阅及 outbox 延迟二次失效协同。

### Key 认证快照的归属

认证缓存与回源并发控制归 `apikey` 模块（Redis 实现在 `apikey/rediscache`，失效 outbox 在 `apikey/postgres`）。

- 副本深拷贝隔离：普通 Key 和复合 Key 每次读取均获得独立请求副本；复合 Key 选组、模型映射、分组回退及单请求修改金额指针、模型列表、区间或分时段均修改副本，不污染共享缓存。
- 连接与关闭安全：Redis 重连时重新订阅并清理缓存；停机时等待在途操作结束后再关闭订阅和 L1 缓存。

## 排查要点

- 区分无可用提供商原因：无分组关联、硬资格过滤、模型或 endpoint 不匹配、临时限流、并发等待超时、快照不可用。
- 脱敏观测字段：日志和 Ops 记录提供商 ID、bucket、平台、模型和过滤原因，不写入 token 和完整凭据。
- 回归测试重点：修改筛选或评分时覆盖缓存命中、数据库回退、粘性命中后失效、并发更新乱序事件，以及流开始后的失败。
- 测试与调度差异：管理端提供商测试成功只说明测试所用协议可用，实际调度仍按请求 endpoint 判断能力。
