# 通知与邮件投递

本文说明通知事件、模板、退订、投递去重和邮件队列的边界。验证码与密码重置凭据由 identity 管理，余额、订阅和账号阈值由所属业务模块判断；通知模块接收已经确定的事件与收件人。

- [事件与模板](#notification_events)：修改业务事件或邮件内容时读取。
- [退订与语言](#notification_preferences)：修改偏好与退订令牌时读取。
- [投递协调](#notification_coordination)：修改去重和失败处理时读取。
- [身份邮件队列](#notification_queue)：修改入队、生成凭据与停机时读取。

- [验证入口](#验证入口)：核实投递和并发契约。

<a id="notification_events"></a>
## 事件与模板

notification 支持 13 类事件：认证验证码、密码重置、通知邮箱验证、团队邀请、订阅购买、订阅到期提醒、余额不足、充值成功、账号额度告警、审核违规、审核封禁、Ops 告警和计划报告。调用方提供事件、收件人、来源标识和模板变量；通知模块不回查订单或账号来重新判断业务结果。

模板按事件和语言保存，包含内置模板、管理员覆盖、预览和占位符校验。HTML 变量默认转义，原始 HTML 只允许明确授权的占位符。模板或配置错误可由业务发送适配使用原正文回退；发送失败或结果不明不会自动重发。Ops 提供报告的真实摘要和详情，预览样例不能混入实际报告。

通知配置和模板使用 settings 存储，SMTP 由 `notification/smtp` 实现。模板管理、SMTP 测试及公开退订位于 `notification/httpapi`。

<a id="notification_preferences"></a>
## 退订与语言

仅标记为可选的事件允许退订；当前为订阅到期提醒和余额不足通知。验证、交易及其他必需事件不能通过退订入口关闭。偏好按事件与收件人保存，读取兼容已有键格式。

退订令牌包含收件人、事件和有效期，使用持久密钥签名，有效期为 365 天。首次生成密钥在同一个服务实例内协调，避免并发生成让刚发出的令牌失效；这不提供跨进程的首次生成互斥。

语言支持中文和英文。调用方可提供语言提示；读取已保存偏好时先查用户，再查邮箱，最后回退英文。邮箱与用户语言记录不承担身份认证。

<a id="notification_coordination"></a>
## 投递协调

同一投递键的查重、发送和成功标记在唯一 NotificationEmailService 实例内串行执行；不同键可以并行，等待锁的请求可以取消。投递身份由事件、来源类型、来源 ID、收件人和提醒键构成，不能随重试生成新的来源来绕过去重。来源类型或来源 ID 缺失时不生成投递键，发送不经过这层查重；验证码等身份邮件还受 identity 自己的凭据和冷却规则控制。

成功标记与 SMTP 接收不属于同一事务。SMTP 已确认但标记保存失败时，投递结果存在不确定性；进程内锁和持久标记都不能保证跨实例恰好一次投递。通知失败也不回滚已完成的资金提交、订单履约或风险处置。

<a id="notification_queue"></a>
## 身份邮件队列

EmailQueueService 使用内存队列，容量 100；构造时未指定有效 worker 数则使用 3 个 worker。构造不启动工作，Start 后处理验证码和密码重置任务，单任务预算 30 秒。队列满或已停止时返回错误，不无限制创建 goroutine；队列不提供进程重启后的任务恢复。

入队保存发送意图，worker 执行时才调用身份能力生成或复用凭据。普通验证码先存后发，通知邮箱验证先发后存；密码重置保留未过期令牌及冷却规则。发送失败不统一回滚凭据，也不统一生成新令牌，详见[身份与租户](identity_and_tenancy.md)。

关闭时先停止接收，再等待已有任务。应用先停止通知生产者，再排空邮件队列；预算耗尽会取消在途 SMTP，并报告排队及正在处理的未完成项。重复停止共享结果，停止后不能重新启动。完整顺序见[系统架构](../architecture/system_architecture.md#startup_and_shutdown)。

<a id="notification_smtp"></a>
## SMTP 与取消

连接测试和实际发送共用建连路径与超时。`smtp_use_tls=true` 首先使用隐式 TLS，仅在服务端返回明文 SMTP 问候时改用强制 STARTTLS；不支持升级则失败。`smtp_use_tls=false` 使用机会式 STARTTLS，服务端不提供扩展时允许既有明文行为。

拨号、TLS 和在途 I/O 都接收 context，采用请求截止时间与连接/I/O 上限中较早者。DATA 已得到成功响应后保留成功结果，不因后续取消或非标准 QUIT 响应重发。发送确认边界与配置说明见[通知与 SMTP](../interfaces/configuration.md#notification_delivery)。

## 验证入口

`backend/internal/notification/service.go` 定义事件、模板、偏好和投递流程，`coordinator.go` 与 `queue.go` 定义并发和生命周期。`fixed_regression_test.go` 覆盖同键投递、首次退订密钥、锁取消和队列排空；SMTP 测试覆盖取消、DATA 确认和 TLS 连接。identity 的邮件挑战测试核实凭据生成与存储顺序。
