## 资源关系

| 资源 | 职责 | 主要关系 |
| --- | --- | --- |
| API Key | 客户端凭据和消费单位 | 属于付款用户，可属于团队；普通 Key 指向一个分组，复合 Key 按前缀映射到多个分组；结算来源可选自动、指定订阅或仅余额 |
| Group | 面向用户的产品和策略单位 | 规定公开或独占、倍率、客户端协议、回退目标、模型规则、RPM 和展示策略；可聚合不同平台的提供商 |
| PricingConfig | 多个分组共享的价格配置 | 一个分组最多关联一个配置；按模型、计费模式、区间和计费来源解析价格，不区分平台 |
| Provider | 实际调用上游的凭据和运行资源 | 通过多对多关系加入分组；保存平台、凭据、代理、并发、优先级、资格、配额和提供商级模型配置 |
| Usage billing record | 只能应用一次的资金或额度变更 | 用 `request_id + api_key_id` 认领，关联付款用户、行为用户、团队、Key、分组和提供商 |
| Usage Log | 已完成请求的可查询记录 | 保存端点、模型链、token 和媒体用量、金额与归属；用于统计和审计，扣费以资金账本为准 |

核心边界与事务规则：

- 分组（客户端产品单位）、价格配置（共享定价单位）和提供商（调度执行单位）分开建模。同一分组可聚合多平台提供商，多分组可共用一张价表并保留各自基础倍率，一个提供商可加入多个分组并在每次请求时单独检查资格。
- 创建或更新分组时，排序锁、提供商关系复制/替换、用户授权清理和调度 outbox 写入在同一事务内完成；outbox 提交后尽力发布。
- 分组容量查询优先使用批量提供商读取（批量失败直接返回错误）；仅存储不支持批量读取时逐组查询并保留成功分组。批量结果包含无提供商的空分组，逐组失败的分组会被省略。
- 价格配置缓存发布独立副本，返回给调用方的嵌套 JSON 配置也是副本，调用方或管理端修改不影响其他请求。
- 普通 Key 的 `user_id` 是付款用户；团队 Key 同时携带 `team_id` 与创建者/行为成员信息，结算命令中 `UserID` 为付款 owner、`ActorUserID` 为实际调用者。Key 还携带状态、过期时间、总配额、滚动金额限额、IP 规则、模型重定向、Fast 策略和 `force_claude_1h_cache` 开关。

<a id="api_key_group_filter"></a>
### API Key 分组筛选

分组采用软删除，普通 Key 保留原分组 ID 供鉴权判断分组是否可用。Key 列表加载关联时隐藏已删除分组并显示「无分组」。`group_id=0` 筛选普通 Key 中没有未删除分组的记录（含未绑定和原分组已删除的 Key）；复合 Key 按自身分组映射展示，不进入该筛选。

<a id="api_key_request_limits"></a>
### API Key 请求上限

- 配置方式：Key 创建和编辑表单支持 `concurrency_limit` 和 `rpm_limit`（非负整数，0 表示不限制；更新省略字段保持原值，传 0 清除限制）。个人与团队 Key 规则一致，用户、团队和分组限额独立检查。
- 预占与计数：完成认证和资金检查后，网关在 Redis 原子预占并发槽和 RPM。并发槽统计进入网关尚未结束的请求（含等待、流式与 Responses WebSocket 活跃轮次）；RPM 统计最近 60 秒获准请求（含上游失败，内部重试与同轮故障转移复用原预占）。
- WebSocket 与复合 Key：Responses WebSocket 每轮计一次 RPM 并在轮次结束释放并发槽（空闲连接由独立连接数限制管理），其他持续中继 WebSocket 建连预占、断连释放；复合 Key 所有分组共用这两项计数。
- 租约与中断：超限返回 HTTP 429 与 `Retry-After`。并发槽每 30 秒续租、租约 2 分钟，请求结束归还，实例异常退出后过期释放。续租失败通过独立内部终止信号取消请求（包括图片、Anthropic、Qoder 流式等与客户端断连脱钩的上游；Responses WebSocket 在客户端断连后继续读取已发出的 HTTP 上游结果，同时监听内部终止信号）。
- 容错与豁免：Redis 命令重放按请求 ID 复用预占，不确定错误时清理该请求并发槽；配置了上限但 Redis 不可用时返回 503。用量查询、模型列表、批任务读取与取消等非消费接口跳过检查。
- 快照传播：请求上限与 `force_claude_1h_cache` 等 Key 级策略随认证快照下发，修改后通过认证缓存失效通知传播到各实例，详见[认证快照](../architecture/provider_scheduling_and_cache.md#认证快照)。

### API Key 结算来源

`api_keys.billing_mode` 和可空 `preferred_subscription_id` 决定资金来源，默认值为 `auto`：

| 模式 | 运行时选择 | 额度不足或失效时 |
| --- | --- | --- |
| `auto` | 优先使用覆盖当前分组的可用订阅，再用付款主体余额 | 订阅与余额可混合分配，不足部分由余额补足 |
| `subscription` | 准入仅使用 `preferred_subscription_id` 指定的付款主体订阅 | 订阅不存在、到期、暂停、不覆盖最终分组或预检额度耗尽时直接拒绝；已放行普通请求若最终费用超额，订阅扣至上限、超出部分扣余额（可为负），其他订阅不参与 |
| `balance` | 仅使用付款主体余额 | 跳过所有订阅解析与分配，订阅额度不变 |

校验与交集规则：

- 设置为 `subscription` 时校验订阅属于实际付款主体且有效（个人 Key 用本人订阅，团队 Key 用 Team Owner 订阅，不能选成员订阅）。
- 套餐未配分组时不限制分组；配置了分组时，指定订阅的 Key 只能选用「用户已有权限」与「套餐分组」的交集。分组不可用回退、复合 Key 选组及 handler 特殊回退都必须重新校验该交集，前端过滤仅作提示。

## 路由决策

模型解析链路依次经过：复合 Key 选组 -> Key 级一跳重定向 -> 分组映射 -> 分组限制 -> 提供商级映射。各层保留输入输出，形成 `requested_model`、`group_mapped_model`、`upstream_model` 和去重映射链，供权限、计价、日志与响应元数据使用。

请求处理顺序固定为：

1. 选组并校验分组权限与客户端协议（HTTP 路由不按分组平台预绑处理器）。
2. 执行模型映射并按组内规则过滤候选提供商。
3. 调度选中提供商，完成协议转换并调用上游。
4. 完成后提交结算。

候选提供商必须同时满足以下条件：

- 属于目标分组（专用入口声明强制平台时还须匹配平台），处于可调度状态且未过期。
- 分组策略与提供商允许当前模型、端点和认证类型，必要时经映射得到最终路由键。
- 具备所需能力或上游资格（图片、视频、Realtime、隐私设置、付费媒体、站点能力等）。
- 未被本次 failover 排除，不在临时不可调度窗口内，配额和限流允许尝试。
- 并发槽、等待队列、优先级、负载和会话粘性共同允许本次选择。

分组绑定、回退与白名单规则：

- 普通 Key 必须绑定分组（历史未绑定 Key 保留凭据但新调用需先选分组）；系统无自动默认分组，也无不经分组的调度路径；未加入任何分组的提供商不参加调度。
- 分组可为「客户端受限」「无效请求」「分组不可用」配置回退目标，Key 的 `fallback_when_group_unavailable` 使用管理员配置的不可用回退分组（未配置则结束请求）。每次换组重验用户、团队、复合 Key、订阅范围、模型和协议权限并检测循环，跨平台回退须在新分组上重验授权。
- 提供商模型范围由非空 `model_whitelist` 限定（支持末尾通配符和单独 `*`）；字段缺失或为空时允许目录未知型号（默认目录对应平台和认证类型，映射可增加自定义名）。`model_mapping` 执行一跳改写，最终型号仍须满足原生协议、端点、认证和媒体资格。统一目录只提供候选、属性和价格，不作为模型权限依据；模型前缀不代表提供商平台，协议透传也不代表支持所有模型。
- OpenAI 兼容 Messages 请求在响应尚未提交给客户端前，若提供商错误命中管理员配置的临时不可调度规则，即使该状态码通常不触发换号也会提升为 failover；命中模型范围规则时先写入模型级临时排除再换号。请求内容或 Grok 内容策略拒绝走各自处理，不进入此路径。

### Fast、推理档位与提供商观测

Fast 档位与 `free_openai_fast`：

- 分组通过 `openai_fast_policy` 配置跟随请求、强制 Fast、强制 Ultra Fast 或关闭加速；全局、分组与 Key 级完整优先级及旧布尔字段兼容见 [Fast 与 Ultra Fast 策略](../interfaces/openai_upstream.md#openai_fast_policy)。
- OpenAI 计费档位从低到高为 Flex、Standard、Fast、Ultrafast。上游明确报告更低档位时按该档位结算；Codex OAuth 返回的 `default` 可能仅为回显，沿用转发档位。
- 价格配置开启 `free_openai_fast` 且最终命中 OpenAI 提供商 `priority`/`fast` 档位时，上游仍发 Fast，用户扣款按同规则以 Standard 重算：Usage Log `total_cost`、提供商统计与额度保留 Fast 成本，`actual_cost`、余额/订阅分配和 Key 配额用 Standard 价。
- 缺 Standard 价时按缺价零成本流程记录且上游保持 Fast；其他平台、普通档位和不可信认证上下文忽略此开关。

推理档位上限与映射：

- `max_reasoning_effort` 和 `max_reasoning_effort_over_limit` 仅作用于客户端显式传入的 `reasoning.effort`、`reasoning_effort` 或 Messages `output_config.effort`（桥接器补出的默认值不计入）。
- 先按分组模型范围映射（精确、前缀或后缀）计算有效档位，再按 `minimal < low < medium < high < xhigh < max` 比较：`downgrade`（默认）降为上限，`deny` 返回本地 403 业务限制错误。`none` 可出现在映射与审计中但不参与上限排序。
- 普通转发层不擅自改写推理档位，Usage Log 同时记录策略前请求档位与最终转发档位。复合 Key 按选定分组策略执行；HTTP Responses、Chat、Messages 转换及 Responses WebSocket 每帧均执行同一判定，策略快照随认证缓存传播。
- 推理映射与上限在执行时按选中提供商、目标协议和模型能力校验（Anthropic 原生与 OpenAI 范围各自校验，混合分组不能强推不支持的值；兼容桥区分 `xhigh` 与 `max` 且保持计费档位不变）。

观测回写与模块边界：

- 网关在 `requeststate.ExecutionHints` 记录规范化健康检查模型，提供商观测输入固定原始模型、规范模型、thinking 和端点；调用后回写只覆盖当前入口负责的字段。
- 用户和分组 RPM 准入、提供商软计数及三区规则归 scheduler（在资金检查后执行，故障按既定规则放行）；五小时费用窗口、批量查询与回填归 billing，scheduler 不具备费用字段写权限。

## 可用性与缓存

认证、分组、价格配置和提供商热路径通过缓存与调度快照降低数据库压力，但以数据库配置和实时调度状态为准。缓存版本、快照结构与传播机制见[提供商调度与缓存一致性](../architecture/provider_scheduling_and_cache.md#失效与恢复)。

以下变更必须主动触发缓存失效或发布新快照（事务提交失败时不发布）：

- Key 状态、限额或映射变化；团队关系变化。
- 分组协议、能力、倍率或路由策略变化。
- 价格配置的分组关联或价卡变化（价格缓存按分组关联、配置和模型规则索引，不依赖平台）。
- 提供商状态、分组关系、凭据、代理、并发或资格变化。

系统区分四种独立状态：

| 状态 | 判定依据 |
| --- | --- |
| Key 可认证 | 凭据、用户、团队、IP 和资源归属有效 |
| Key 可消费 | 在可认证基础上，余额、订阅、Key 配额和滚动限额允许 |
| 分组可路由 | 产品策略允许该请求，且组内有满足模型和协议要求的提供商 |
| 提供商可调度 | 还取决于瞬时并发、上游限流、配额、临时封禁和端点能力 |

模型列表只表示当前身份理论上可请求的集合，短暂无空闲并发不意味着永久不可用，实际请求在调度时重验实时状态。

<a id="provider_spending_limits"></a>
### 提供商本地消费限额

- 适用范围与统计口径：API Key 和 Bedrock 提供商支持日、周、月和累计总限额（USD，按提供商成本 × 提供商倍率累计，0 或未设为不限）。任一启用维度达上限即从调度排除，已获准在途请求仍按最终用量结算。
- 窗口重置模式：默认滚动模式自首次消费起计 24 小时、7 天、30 天，到期后下次结算同步刷新用量和起点。固定模式按共用 `quota_reset_timezone` 和各维度重置小时计算；`quota_monthly_reset_day` 范围 1 至 31，当月无该日取月末（如 31 日在平年 2 月取 28 日，3 月恢复 31 日）。
- 夏令时统一规则（Go 调度、配置计算和 PostgreSQL 结算一致，兼容半小时偏移）：春季跳变导致本地时刻不存在时按跳变前 UTC 偏移顺延一个跳变间隔；秋季回拨导致时刻重复时取后一次（如纽约 2026-11-01 01:00 取第二次 01:00 即 06:00 UTC），后续周期恢复配置小时，与 [PostgreSQL 歧义时间处理](https://www.postgresql.org/docs/current/datetime-invalid-input.html)一致。
- 月字段存储与编辑：月限额字段保存在提供商 Extra（`quota_monthly_limit`、`quota_monthly_used`、`quota_monthly_start`、`quota_monthly_reset_mode`、`quota_monthly_reset_day`、`quota_monthly_reset_hour` 和派生 `quota_monthly_reset_at`）。编辑锁定行并保留最新用量（过期固定窗口按新规则归零），手动重置清空所有维度，复制提供商继承限额与规则并归零用量。
- 结算、快照与告警：结算在资金事务内累计月用量并在首次跨限写调度 outbox；轻量调度快照保留月配置与起点，调度和管理端均忽略过期窗口旧用量；月告警沿用固定金额或百分比阈值并优先读本次事务返回用量。

## 价格规则

<a id="group_model_pricing"></a>
### 共享模型价卡与计费设置

价卡解析与金额计算集中在 `billing/pricing`。分组只保存基础倍率 `rate_multiplier`，其余规则统一保存在共享价格配置中。

解析优先级与默认设置：

1. 先查分组关联的共享价格配置（配置级设置无论是否命中模型条目都生效）。
2. 未命中、未关联配置或配置已停用/删除时，回退统一默认设置与统一模型目录定价。
3. 默认配置值：内置长上下文开启、高峰关闭、`free_openai_fast` 关闭、批量图片折扣 `0.5`、预扣倍率 `0.6`；可空搜索与语音单价读取目录 `_billing_defaults`（手填 0 为免费）。

`reference_model` 与单价继承：

- 价格条目的 `reference_model` 指向同一配置快照内的具体目标模型，目标的单价、计费模式、区间、分时、缓存和服务层级倍率一并生效。来源支持末尾通配符，目标必须具体且不能命中任何映射来源；映射条目不可叠加覆盖，目标缺价时保持缺价。结算和媒体目录查价使用目标查价型号，Usage Log 保留请求模型链；提供商成本规则独立计算且拒绝 `reference_model`。
- 手填单价（含 0）覆盖基础价。未填区间桶、区间倍率及未命中区间的请求回退价卡默认价，再回退内置价；仅设 Fast/Flex、Max 或分时倍率的条目继承内置价格桶、来源和模式，不会给缺价模型赋予免费基础价；无基础价的纯倍率区间返回 `ErrModelPricingUnavailable`。
- 提供商 `rate_multiplier` 只影响提供商成本统计和额度累计，不影响用户扣款；Qoder 沿用同一价格回退规则。`PricingAt` 为零时价格配置分时关闭（目录分时独立算时刻；网关在结算开始时读取配置级设置，认证快照不含分组价格字段）。
- 资金分配分别携带订阅倍率（首订阅 `ActualCost / TotalCost`）和余额倍率；仅 token 模式对两者及套餐倍率叠加高峰因子，图片、视频和按次模式高峰因子固定为 1，订阅超额按余额倍率结算。

计费模式分派、媒体与图片缓存：

- 结算按价卡声明的计费模式分派，与模型名无关。`image` 按尺寸查价；`per_request` 依次匹配非空标签 -> 无标签的总输入上下文区间 -> 显式默认按次价（尺寸标签不参与上下文匹配），全未命中返回缺价（数值默认 0 不代表免费）。
- 普通网关按模式乘数结算：静态图片 × 张数、GIF × 帧数、视频 × 总输出秒数、按次 × 输出数、token × 实际用量。创作台和批量图片按张预占与结算，固定单张价取自图片价卡或无上下文按次价卡（输入未知时不接受上下文按次价卡）；仅 token 价卡时查目录按张价（不拿每 token 价当单张价）；已提交任务按提交快照结算。
- GIF 用 `image_count` 记文件数、`image_frame_count` 记完整 GIF 字节解析的计费帧数（按次价卡仍按文件数，token 价卡按上游用量不乘帧数）。创作台按单帧价预占请求帧数并在结果事务保存实际帧数，恢复结算不依赖可下载字节；静态历史行新字段为 0，旧指纹兼容。
- 图片缓存输入是聚合缓存命中的子集，仅上游明确返回图片缓存细分时单独定价（绝不按输入图片数推算）。流式非终态上报的正值图片缓存计数与其他 token 桶一并保留以防终态缺失 usage；管理员设置的聚合缓存单价同时覆盖图片缓存子集。

### 兼容协议的计费候选

Kimi、Zhipu、DeepSeek 等 Anthropic 兼容提供商实际并非 Claude 模型，计费候选不按客户端传入的 Claude 名借用其他型号价格：仅当价格配置提供有效单价或显式指向已定价的 `reference_model` 时才保留该候选，映射后的实际模型按常规解析。

候选全部被过滤或全空时返回 `ErrModelPricingUnavailable`，按现有流程记录零成本告警并保留 Usage Log。

### 长上下文

- 长上下文定价与提供商能力无关。价格配置存在有效 token 区间时按总输入命中区间且不叠加模型内置倍率，不受 `long_context_pricing_enabled` 开关影响；无有效区间时由该开关控制是否应用内置阈值和输入/输出倍率（默认开启）。
- 总输入量 = 输入 + 缓存创建 + 缓存读取，达标后整次请求输入与输出侧分别乘对应倍率。目录 `input/output_cost_per_token_above_*k_tokens` 加载时换算为阈值和倍率，条目手填任一 `long_context_*`（含 `0`）优先覆盖。本地补充仅填缺失维度且不覆盖目录现价，非法字段或非对象条目拒绝整次目录更新；覆盖文件不参与定价。
- 模型广场上下文区间价与同分组倍率下的 `ActualCost` 一致；普通提供商与 Spark 影子提供商在同条件下价格一致；提供商 `extra` 中已废弃的 OpenAI 开关不参与判断；`long_context_billing_applied` 仅在实际增费时为真。

### 提供商成本

- 提供商成本基数取 `provider_stats_cost`（非 `nil` 时，0 表示成本为零），为 `nil` 时回退 `total_cost`；提供商统计与 `quota_used` 统一按 `基数 × 提供商 rate_multiplier` 计算，用户资金和 Key 配额始终使用 `ActualCost`。
- 提供商统计优先匹配独立提供商成本规则（自定义统计价直接作最终基数，不乘服务层级倍率），未命中时回退网关默认模型价（按 Usage Log 最终服务层级与长上下文倍率计算），缺价走日志层 `nil` 回退。
- 共享价卡与提供商成本价卡共用模型命名空间（单表内同名模型仅一条跨平台规则），提供商成本规则按分组、提供商条件和排序独立保存。旧价卡迁移冲突见[部署与数据库迁移](../operations/deployment_and_migrations.md)，分组白名单见[分组模型与功能策略](gateway_policy_controls.md#group_routing_policy)。

### 计费维度

| 维度 | 可选值与规则 |
| --- | --- |
| 计费模型来源 | 客户端请求模型、分组映射模型、最终上游模型（选上游模型时须等选定提供商并完成最终映射后定价格，不影响白名单阶段） |
| 计费模式 | token、按次、图片、视频等，写入时拒绝负值并校验对应必填字段 |
| token 桶 | 输入、输出、缓存创建、缓存读取，及适用模型的图片输出 token |
| 倍率 | 系统默认、分组、用户覆盖、订阅套餐分组倍率及高峰因子（高峰按结算时刻与配置时区计算，仅作用于 token） |

定价模式冲突检测与缓存键归一化共用规则：仅忽略大小写与首尾空白，保留点号、短横线、日期和档位后缀，前后端一致。

### 分时价格

分组和价格配置的 token 模式定价支持 `time_pricing`（普通请求按结算时刻，OpenAI WebSocket 按 turn 开始时刻，配置损坏或无法加载时按 `1x`）：

- 使用 IANA 时区和每日左闭右开区间（`HH:mm` 或 `HH:mm:ss`），区间不可重叠；结束时间 `00:00` 表示当天 24:00，跨午夜须拆成两段。
- 倍率为有限数，最小 `0.01`，最多两位小数。
- 仅作用于 token 输入、图片输入、输出和缓存桶；按次、图片、视频不受影响，也不复制到提供商统计规则。
- 仅设倍率的分组条目未配分时时继承价格配置，设置后整体替换（时段外为 1x），任一时刻仅一层分时倍率生效；分组高峰倍率另外叠加。

### Max 推理倍率

token 计费支持 `max_reasoning_effort_multiplier`（有限正数，`1` 不加价，缺省不加价），仅在最终转发档位为 `max` 时生效。它作用于全部 token 桶并与服务层级、区间和分时倍率叠加，不作用于按次、图片、视频及搜索附加费。

被策略降档的 `max` 请求按最终档位结算；提供商统计回退默认价时按最终档位算，自定义统计价不叠加用户倍率，提供商统计规则拒绝该字段。

### 缓存写入分档

| 平台/类型 | 分档字段 | 继承与回退规则 |
| --- | --- | --- |
| GPT | `cache_write_30m_price`、`cache_write_12h_price` | 可空独立覆盖本层统一写入价；未填先用本层统一写入价，再走价卡与目录继承，明确 0 为免费；用户结算与提供商统计仅用与聚合数一致的上报分档，写入总数只计入输入上下文一次，历史行保留 NULL |
| Claude 及通用 | `cache_write_price`（5m）、`cache_write_1h_price`（1h） | 适用于默认价、token 区间和提供商统计价，明确 0 为免费；1h 为 NULL 或用量缺分档数据时两档均按 5m 聚合价计算 |

### Grok 媒体、搜索和语音

- 视频：按输出秒数计价。价格配置 `video` 模式支持规范化自定义分辨率标签，先匹配分辨率再取显式默认每秒价（0 为免费，缺价不转 480p）；无有效价卡时查目录完整型号与分辨率单价。时长优先取完成响应、其次创建快照、全缺用 8 秒（正数均计费）；异步创建不扣费，首次观察到完成时以任务级稳定 request ID 结算。
- 搜索：按 `search_price_per_1k` 与调用次数计费，附加在 token 费用上；独立 `/web_search` 与 `/x_search` 纯工具请求可单独结算。
- 语音：Realtime、TTS、STT 分别按每分钟、每百万字符、每小时计价。Realtime 握手和纯文本会话不收费，任一方向出现非空音频后按连接会话时长结算。

<a id="missing_model_pricing"></a>
### 缺价处理

调用前预检范围与拒绝语义：

- 文本预检：Responses、Chat Completions、Messages 在选定提供商后、调用上游前检查；Gemini `generateContent` / `streamGenerateContent` 在每次尝试前检查（覆盖 Gemini 与 Antigravity，`countTokens` 跳过）；Responses WebSocket 每轮重检（含透传与 HTTP 桥接）。
- 查价规则：复用结算的模型来源、共享价格配置和目录（手动零价与有效区间放行，缺基础价的倍率条目拒绝），先按协议回退解析上游协议再选对应计费模型。`/responses/compact` 复用 `CompactExecutor` 顺序（提供商 `compact_model_mapping` -> 全局 `gateway.openai.compact_model` -> 常规映射），最终扣费仍按价卡模型来源查价。
- 拒绝行为：未开始响应时 HTTP 返回 400（OpenAI 错误码 `model_pricing_unavailable`，Gemini 返回 Google 400 `INVALID_ARGUMENT`），已流式则追加错误事件；WebSocket 按本地策略关闭并提示管理员配置价格或映射。
- 中断与释放：预检拒绝带 `ErrModelPricingRejected` 标记，文本尝试循环收到后立即结束并释放并发槽，不触发上游失败反馈、重试或结算。
- 内部模型：`codex-auto-review` 等目录未收录模型须手动配价（可设 0 免费）或映射到已定价模型；出现在支持列表仅代表可转发。
- 媒体、操作与未知模型：图片模型走媒体计价（文本请求声明图片工具仍查文本价）；其他媒体、操作价（缺默认价报 `operation pricing unavailable`；发布包仅补充已核实的 OpenAI Web Search、xAI TTS、REST STT，混合搜索与通用 Realtime 无默认价）及放行后改价导致的结算缺价保留缺价零成本记录。所有平台未知型号均按缺价处理，不借用同系列、默认型号或模型链其他型号价格。

<a id="usage_settlement"></a>
## 用量结算

模块职责与准入顺序：`gateway/completion.Recorder` 归一化供应商用量、选择模型和请求 ID 并构造 Usage Log；billing 负责资金准入、查价、分配和扣费提交。资金准入严格在 scheduler RPM 之前执行（Qoder 等待结束后只复查资金）。用户日/周/月平台额度已移除，余额、订阅、团队、Key 限额和提供商上游额度各自生效。

事务与计费键边界：

- `Funds.Settle` 始终开启独立 PostgreSQL 事务，不会自动加入 context 中的外层 Ent Tx；外层身份或权益事务需要同连接写入时显式传入 Ent Tx，由外层负责提交、回滚、缓存失效与通知。
- Usage Log 的 `request_id` 表示本地请求，`billing_key` 表示资金去重键（存储在资金命令、账本和去重表的 `request_id` 列中）；跨版本规则见[请求 ID 与请求查询](../operations/request_lookup.md#billing_identity)。

标准结算流程：

1. 校验 `request_id` 非空并规范化 `UsageBillingCommand`，基于归属、用量、价格和可选请求 payload 摘要生成幂等指纹。
2. 在 PostgreSQL 事务中插入 `(request_id, api_key_id)` 去重记录：已有同指纹记录视为已结算直接返回，指纹不同则报冲突且不扣费。
3. 先用 `FOR NO KEY UPDATE` 锁定付款用户，再按固定顺序读取并锁定可用订阅，防止并发超额消费。
4. 按 Key 结算模式分配资金：`auto` 先分适用订阅再扣余额；`subscription` 仅锁定并分配指定订阅（已放行普通请求超额部分按余额倍率记为欠费）；`balance` 跳过订阅只扣余额。分别记录订阅与余额的金额和有效倍率。
5. 同事务累计团队成员周期用量、API Key 总配额和滚动窗口；提供商额度按 `COALESCE(provider_stats_cost, total_cost) × provider_rate_multiplier` 累计（成本为零不累计）。
6. 提交成功后返回 `Applied`、新余额、订阅分配及提供商和 Key 配额状态；遇到 PostgreSQL 死锁时外层开启新事务做有限次重试。

结算专项约束：

- 软删除 Key 并发：软删除仅拦截后续请求，已放行请求按原 Key ID 正常更新总配额和滚动用量（凭据、删除标记和状态不变；Key 确实不存在时事务失败）。删除与结算并发时无论谁先提交费用均保留，重复提交不重复扣费。
- 金额量化：`users.balance`、Key 配额和滚动窗口类型为 `NUMERIC(20,8)`，参与 SQL 加减前统一按 PostgreSQL half-away-from-zero 量化到 8 位小数，避免第 9 位边界舍入相反产生 `1e-8` 差额。幂等指纹基于量化前原始金额生成以保证升级重试兼容；10 位精度的订阅与用量数据在入口不提前截断。
- 订阅分配与超额：订阅须同时满足生效时间、状态、周期额度和分组覆盖。`subscription` 模式在已放行普通请求超额时封顶订阅并扣余额（可负），后续新请求仍按订阅快照拦截；若指定订阅不存在、失效或不覆盖最终分组，整笔结算失败且不回退余额。
- 异步资金来源与团队归属：结算命令和指纹携带结算模式与指定订阅 ID，异步落账不受后续 Key 改配影响；团队请求锁定付款 owner（`UserID`）并将成员累计用量记在 `ActorUserID`。
- 异步任务预占与释放（批量图片、创作台）：通过 `Funds.Reserve`、`Funds.Capture`、`Funds.Release` 携带 scope、任务 ID 和原预占动作 ID（未知 scope 在事务前拒绝）。任务表更新参与同一 SQL 事务并在失败时同回滚，死锁重试重建事务和参与者；scope 与参与信息不入历史指纹以兼容 v1/v2/v3 快照。
- 任务快照与超额捕获：任务提交时持久化分配快照并用同一幂等 request ID 结算、释放或回滚，指定订阅须在提交上游前全额覆盖预占。默认拒绝超额捕获；创作台 GIF 实际帧数超出时显式启用 `TaskOverageChargeBalance`，保留原订阅上限并按保存的余额倍率补扣超额（可负），仅超量捕获时加入指纹，与 Key/成员用量差额、任务标记和去重同事务提交。

<a id="system_model_cost"></a>
## 系统模型调用成本

- 覆盖范围与关联：分组探针、手动/定时提供商测试和主动调用模型的额度探测均按上游尝试落录，`request_source` 区分 `user`、`group_probe`、`provider_test`、`scheduled_test` 和 `quota_probe`（`request_type` 保留同步/流式传输分类），多协议尝试或重试经 `system_usage.parent_request_id` 关联。
- 模型字段：`model`/`requested_model` 记入口模型，`upstream_model` 记上游模型，分组映射模型存系统元数据并参与缺价回退；普通请求保留去重映射链，托管图片承载模型与图片工具模型分开记录。
- 归属与计价：系统记录无付款用户、行为用户、团队和 API Key（数据库与 HTTP 为空，Go 为零值），手动操作人仅存系统元数据且不计入用户统计，用户实扣、余额与订阅分配均为零。
- 成本计算：`usage.SystemRecorder` 用共享定价服务计算基础金额和提供商成本（有分组取分组配置，否则取目录），区分完整/部分/缺失用量，缺价或缺少计价数量标为未知（明确 0 为免费）；金额按本地规则计算，非供应商账单回执。
- 原子去重账本：`billing_system_usage_entries` 按上游尝试 ID 保存成本证据和指纹，在同一 SQL 事务内完成账本认领、提供商限额累计、调度 outbox 与使用记录写入。任一步失败全回滚；同证据重放不重复累计且不恢复已清理日志，同 ID 不同证据报冲突。不触碰用户资金、订阅和 Key 配额；日志清理保留该账本，备份归入用量记录组。

## 记录与对账

### 完成快照、账本与异步日志

- HTTP、SSE、媒体和 WS turn 提交后台完成任务前，同步捕获不可变主体、资金来源、报文、模型及所需计费字段快照（不保留凭据与原始请求体），不再读取会变化的请求对象。
- 请求 ID 前缀优先级、上游自定义 Header、无 HTTP 请求 ID 的 WS、UTF-8 列宽截断、WS turn 固定时刻与额度更新均按既定规则执行；普通完成、Cyber 失败补记和 Live 零费用日志各自保持独立资格规则。
- 完成队列驻留内存、不持久化；停止时同时等待排队任务和同步溢出任务，停止后不可扩缩容。队列或进程超时不代表资金已提交，资金状态以 billing 去重记录和事务结果为准。
- 资金事务提交后尽力写入 Usage Log：日志失败不回滚已扣费用，重试写日志不重复扣费。结算失败时日志保留 token 与基础成本、`ActualCost` 记为 0 并返回错误（不算已扣费）。余额和提供商额度阈值通知优先使用事务返回的配额状态（缺失时回源读取），由 notification 异步投递，不参与资金提交。

### 导出指标、上游模型校验与分布维度

- 导出单位：用户 CSV 与管理员 Excel 在表头标注单位（用户实扣用配置的余额单位，标准费用、分项成本与提供商成本用 USD），数据行保持数值精度，单位设置不改账务金额。
- 输出速度 TPS：用户、团队、管理员记录与 Ops 模型平均速度统一使用单次上游尝试平均速度 `output_tokens × 1000 ÷ (最后有效内容到达时刻 − 上游调用开始时刻)`（输入来自 `usage_logs.timings` 和输出 token）。
- TPS 边界与格式：仅流式正常完成、usage 完整、输出 token 为正、起止观测齐全且时长为正时计算（含单块输出），否则页面显示 `-`、导出留空；服务端保留一位小数（页面 `tok/s`，Excel 数值单元格保留一位小数）。全局首字/首包设置不影响 TPS，边界定义见 [HTTP 接口](../interfaces/http_api.md#response_errors)。
- Usage Log 归档字段：保存付款用户、行为用户/团队、Key、提供商、分组、请求 ID、入口与上游端点、执行提供商平台快照、模型链、计费来源、token/媒体明细、基础与实际成本及 billing type。管理端明细列设置新增默认隐藏的请求 ID 列（升级旧偏好仅追加隐藏项，不覆盖已有选择）。新增协议或用量桶须同步更新解析、成本计算、结算指纹、日志 schema、聚合查询和对账测试。
- 上游响应模型校验（仅管理员可见）：保存转换与别名恢复前的上游原始声明 `upstream_response_model` 和可空 `upstream_model_mismatch`（与实际出站模型忽略空白和大小写比对，版本、日期、供应商前缀差异均算不一致；无声明或历史行保持 NULL，不用请求模型补值，不参与定价、扣费、分布和路由）。
- 不一致展示与导出：管理端仅明确不一致时在映射链下方显示橘色箭头、响应模型 ID 及悬浮对比，导出包含两项字段，普通用户与团队 DTO 不返回；单条、批量和降级写入保持字段顺序一致。
- 明细与分布维度：`requested_model` 保留客户端原始提交名（含复合前缀与 Key 别名）供单条审计；模型分布的请求维度使用重定向后的内部请求模型 `model`（同内部模型聚合为一项），上游分布用实际 `upstream_model`，映射分布用 `内部请求模型 -> 上游模型`。

## 领域不变量

- 分组定义产品策略，价格配置定义共享定价，提供商定义执行能力；三者 ID 互不通用。
- 客户端模型、分组映射模型和上游模型分别保存，限制、计费和响应恢复各自读取明确来源；统一目录只提供候选、属性和价格，不作为模型权限依据。
- 缓存只加速判断；已禁用的用户、团队、Key、分组或提供商命中缓存也无法继续执行。
- 资金、订阅、团队成员、Key 和提供商额度变更必须在同一幂等事务内完成。
- 公开长上下文区间价等于同倍率下的用户实扣单价；同一计费规则下提供商平台与 extra 不改用户价格；价格配置区间不与模型内置倍率叠加。
- 提供商统计与提供商额度共用同一成本基数和提供商倍率；用户资金与 API Key 配额只使用 `ActualCost`。
- 指定订阅的 Key 最终分组必须被套餐覆盖；预检发现订阅失效或额度耗尽直接拒绝，已放行成功的普通请求由订阅封顶承担、超额记余额欠费，不超扣订阅也不产生零计费。
- `request_id + api_key_id` 相同但指纹不同时按冲突拒绝。
- Usage Log 不代表扣费已提交，对账以去重记录与实际资金、权益变化为准。
- 新增计费类型时，测试须覆盖订阅与余额混合分配、团队归属、重复提交、死锁重试和日志写入失败。
