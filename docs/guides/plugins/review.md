# 插件审核标准

审核对象包括公开源码、发布资产、manifest 权限和实际业务效果。索引签名只证明来源，不证明代码安全或业务逻辑正确。

## 代码与资产

核对仓库、标签、构建流程及 Release 资产对应关系，保留第三方许可证。源码与前端 bundle 应可审阅，不接受混淆代码、隐藏的环境读取或与功能无关的数据上传。检查包中没有密钥、数据库文件、路径穿越、符号链接、设备节点或额外执行文件。

声明最低宿主版本、平台、页面和接口。HTTP 路由按最小需要设置 public/user/admin；公开路由不能仅凭请求正文中的 user_id 就执行敏感动作。前端代码共享宿主上下文，应避免读取或传出认证存储，不得把 HostApi 的小接口当成浏览器沙箱。

## 权限、资金与权益

逐项解释 user、wallet、redeem、subscription、usage、payment、catalog、notify 等权限用途。邮箱与身份绑定可能包含个人信息，应只查询当前功能需要的字段，不记录无关用户资料。

资金和权益写入说明接收者、额度、单次金额或天数、每日次数与稳定幂等键。测试网络错误后的重试、参数变化、重复键、不同用户、余额不足、套餐不允许及额度为零。wallet.credit 不应假装成用户真实充值，订阅码的有效天数在签发时固定。

邮件先认领再投递；未知投递结果需要人工核对，不应更换键自动重发。定时任务必须支持取消、避免无限循环，并在宿主停止时释放资源。

## 更新与失败恢复

测试从上一版本迁移配置，确认 secret 不会变成公开普通字段。检查已完成幂等记录和 KV 在更新、回滚、卸载保留数据及重装后仍有效；代码回滚不能恢复资金或撤回邮件。

至少验证 Init 失败、处理器 panic、请求超时、超大响应、脚本加载失败和宿主重启。记录实际命令、版本、平台与结果，不把 mock 验证、静态工作流检查或编译成功写成真实部署验收。

提交者填写索引 PR 模板；维护者核对新 publisher 的所有权、所有权限用途、代码与资产对应关系及无混淆要求，再批准收录。
