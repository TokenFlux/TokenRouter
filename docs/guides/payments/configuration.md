# 支付系统配置指南

TokenRouter 内置支付系统，支持用户自助充值、购买套餐和发放订阅权益，不需要另外部署支付服务。其他管理员手册见[指南目录](../index.md)；订单状态机和结算规则见[支付与权益 Project Doc](../../domains/payments_and_entitlements.md)。

## 支持的支付方式

| 服务商 | 支付方式 | 说明 |
| --- | --- | --- |
| EasyPay（易支付） | 支付宝、微信支付 | 兼容易支付协议的第三方聚合支付 |
| 支付宝官方 | 桌面二维码扫码、移动端跳转支付宝或当面付唤起 | 直接对接支付宝开放平台；移动端默认使用手机网站支付（WAP），也可以选择当面付二维码唤起支付宝 |
| 微信官方 | Native 扫码、H5、公众号和 JSAPI 支付 | 直接对接微信支付 APIv3，按终端环境自动选择 |
| Stripe | 银行卡、支付宝、微信支付、Link 等 | 国际支付，支持多币种 |
| Airwallex（空中云汇） | Airwallex 托管收银台支持的支付方式 | 国际支付，支持测试和生产 API、多币种和可选的平台提供商 |

支付宝官方、微信官方和易支付可以同时作为后台的服务商实例存在，但前台只展示"支付宝"和"微信支付"两个按钮。管理员需要为每个按钮选择一个支付来源：官方或易支付。官方渠道直接对接 API，资金直接进入商户账户，手续费较低；易支付通过第三方平台聚合，接入门槛较低。

第三方支付渠道的费率、结算、准入和合规要求会变化，请以服务商当前的官方条款为准。TokenRouter 不为任何第三方支付服务商做担保或背书。

## 快速开始

1. 进入管理后台的"设置 → 支付设置"标签页。
2. 开启"启用支付"。
3. 配置基本参数（金额范围、超时时间等）。
4. 在"服务商管理"里添加至少一个服务商实例。
5. 用户就可以在前端页面充值了。

## 系统设置

在管理后台的"设置 → 支付设置"里配置以下参数。

### 基本设置

| 设置项 | 说明 | 默认值 |
| --- | --- | --- |
| 启用支付 | 开启或关闭支付系统 | 关闭 |
| 商品名前缀 | 支付页面显示的商品名前缀 | 无 |
| 商品名后缀 | 商品名后缀（例如"元"） | 无 |
| 最低金额 | 单笔最低充值金额 | 1 |
| 最高金额 | 单笔最高充值金额（留空表示不限） | 无 |
| 每日限额 | 每个用户每天累计充值的上限（留空表示不限） | 无 |
| 订单超时时间 | 订单超时的分钟数，至少 1 分钟 | 30 |
| 最大待支付订单数 | 同一用户同时存在的待支付订单上限 | 3 |
| 负载均衡策略 | 有多个服务商实例时的选择策略 | 轮询 |

### 支付宝移动端当面付唤起

"支付宝移动端当面付唤起"默认关闭，只对前台路由到支付宝官方的移动端订单生效。开启后，服务端调用 `alipay.trade.precreate` 获取动态二维码，前端立即用支付宝 Scheme 尝试唤起 App；页面没有进入后台时，自动显示动态二维码备用页，并继续轮询订单状态。桌面端仍然是"优先当面付二维码，回退到电脑网站支付"。

- 需要为这个支付宝应用开通"当面付"或"扫码支付"；没有开通时保持关闭。
- 管理后台的开关保存为 `ALIPAY_MOBILE_PRECREATE_DEEP_LINK`，支付行为以该设置为准；同名环境变量已不再覆盖它。
- 和"支付宝强制二维码支付"同时开启时，当面付唤起优先。关闭这个开关，移动端恢复为手机网站支付。

### 前台可见支付方式的路由

用户看到的支付方式是统一的，不区分官方渠道还是易支付：

- 支付宝：后台启用后，还要指定这个按钮路由到"支付宝官方"还是"易支付支付宝"。
- 微信支付：后台启用后，还要指定这个按钮路由到"微信官方"还是"易支付微信"。
- 同一个可见的支付方式，同一时间只能路由到一个来源。
- 没有选择支付来源时，即使按钮已经开启，前台也不会显示这个支付方式。

### 负载均衡策略

| 策略 | 说明 |
| --- | --- |
| 轮询（round-robin） | 按顺序轮流分配给各个服务商实例 |
| 最少金额（least-amount） | 优先分配给当天累计金额最少的实例 |

### 取消频率限制

防止用户频繁创建、取消订单：

| 设置项 | 说明 |
| --- | --- |
| 启用限制 | 开关 |
| 窗口模式 | 滚动窗口或固定窗口 |
| 时间窗口 | 窗口长度 |
| 窗口单位 | 分钟或小时 |
| 最大次数 | 窗口内允许取消的最大次数 |

### 帮助信息

| 设置项 | 说明 |
| --- | --- |
| 帮助图片 | 充值页面显示的联系二维码等图片（支持上传） |
| 帮助文本 | 充值页面显示的说明文字 |

## 服务商配置

不同的服务商需要不同的凭据和参数。在"服务商管理 → 添加服务商"里选择类型后填写。

添加服务商时，异步回调地址（Notify URL）和同步跳转地址（Return URL）由系统根据站点域名自动生成，管理员只需要确认域名正确。

### EasyPay（易支付）

兼容任何遵循 EasyPay 协议的支付服务商。

| 参数 | 说明 | 必填 |
| --- | --- | --- |
| 商户 ID（PID） | EasyPay 商户 ID | 是 |
| 商户密钥（PKey） | EasyPay 商户密钥 | 是 |
| API 地址 | EasyPay API 的基础地址 | 是 |
| 支付宝通道 ID | 指定支付宝通道 | 否 |
| 微信通道 ID | 指定微信通道 | 否 |

### 支付宝官方

直接对接支付宝开放平台。移动端默认跳转到支付宝手机网站支付；开启"支付宝移动端当面付唤起"后，改为调用当面付，前端尝试打开支付宝 App，失败时显示动态二维码备用页。桌面端优先使用当面付返回的扫码串；商户没有开通当面付时，回退到电脑网站支付，并把收银台链接返回给前端，用于显示二维码或直接打开支付页。

| 参数 | 说明 | 必填 |
| --- | --- | --- |
| AppID | 支付宝应用的 AppID | 是 |
| 应用私钥 | RSA2 应用私钥 | 是 |
| 支付宝公钥 | 支付宝公钥 | 是 |

### 微信官方

直接对接微信支付 APIv3，支持 Native 扫码支付、H5 支付，以及微信环境内的公众号和 JSAPI 支付。

| 参数 | 说明 | 必填 |
| --- | --- | --- |
| AppID | 微信支付 AppID | 是 |
| 商户号（MchID） | 微信支付商户号 | 是 |
| 商户 API 私钥 | 商户 API 私钥（PEM 格式） | 是 |
| APIv3 密钥 | 32 位 APIv3 密钥 | 是 |
| 微信支付公钥 | 微信支付公钥（PEM 格式） | 是 |
| 微信支付公钥 ID | 微信支付公钥 ID | 是 |
| 商户证书序列号 | 商户证书序列号 | 是 |

### Stripe

国际支付平台，支持多种支付方式和币种。

| 参数 | 说明 | 必填 |
| --- | --- | --- |
| Secret Key | Stripe 密钥（`sk_live_...` 或 `sk_test_...`） | 是 |
| Publishable Key | Stripe 可公开的密钥（`pk_live_...` 或 `pk_test_...`） | 是 |
| Webhook Secret | Stripe Webhook 签名密钥（`whsec_...`） | 是 |
| 币种 | 三位的支付币种代码，例如 `CNY`、`USD` | 是 |

### Airwallex（空中云汇）

通过 Airwallex 托管收银台完成国际支付。测试环境和生产环境，需要分别选择对应的 API 地址和凭据。

| 参数 | 说明 | 必填 |
| --- | --- | --- |
| Client ID | Airwallex API Client ID | 是 |
| API Key | Airwallex API Key | 是 |
| Webhook Secret | Airwallex Webhook 签名密钥 | 是 |
| API 地址 | 生产环境使用 `https://api.airwallex.com/api/v1`，测试环境使用 `https://api-demo.airwallex.com/api/v1` | 是 |
| 国家代码 | 两位的 ISO 国家代码，默认 `CN` | 是 |
| 币种 | 三位的支付币种代码，例如 `CNY`、`USD` | 是 |
| Provider ID | 平台提供商或被授权提供商的 ID | 否 |

## 服务商实例管理

同一种服务商可以创建多个实例，用于分流和风控：

- 按轮询或最少金额策略分流订单。
- 每个实例可以单独设置单笔最小、最大金额和每日限额。
- 每个实例可以单独启用或停用，不影响其他实例。
- 每个实例可以单独开启或关闭退款。
- 每个实例可以选择自己支持的部分支付方式。
- 可以拖拽调整实例的顺序。

### 实例限额

| 限额项 | 说明 |
| --- | --- |
| 单笔最小金额 | 这个实例接受的最小订单金额 |
| 单笔最大金额 | 这个实例接受的最大订单金额 |
| 每日限额 | 这个实例每天累计交易的上限 |

分流时，系统自动跳过超出限额的实例。

## 回调配置

订单能否到账，取决于支付回调能否送达，所以请按下面的说明配置。

### 回调地址

添加服务商时，系统根据站点域名自动生成回调地址：

| 服务商 | 回调地址 |
| --- | --- |
| EasyPay | `https://your-domain.com/api/v1/payment/webhook/easypay` |
| 支付宝官方 | `https://your-domain.com/api/v1/payment/webhook/alipay` |
| 微信官方 | `https://your-domain.com/api/v1/payment/webhook/wxpay` |
| Stripe | `https://your-domain.com/api/v1/payment/webhook/stripe` |
| Airwallex | `https://your-domain.com/api/v1/payment/webhook/airwallex` |

把 `your-domain.com` 换成实际的域名。EasyPay、支付宝和微信的回调地址，在添加服务商时自动填入，不需要手动配置。

### Stripe 回调设置

1. 登录 [Stripe Dashboard](https://dashboard.stripe.com/)。
2. 进入 Developers → Webhooks。
3. 添加端点，填写回调地址。
4. 订阅事件：`payment_intent.succeeded`、`payment_intent.payment_failed`。
5. 把生成的 Webhook Secret（`whsec_...`）填进服务商配置。

### Airwallex 回调设置

1. 在 Airwallex 管理后台创建 Webhook，填写上表里的回调地址。
2. 订阅支付成功和支付失败相关的事件。
3. 把 Webhook 签名密钥填进对应的 TokenRouter 服务商实例。
4. 先用 Demo API 和测试凭据完成下单、回调和补单的验证，再切换到生产 API。

### 注意事项

- 回调地址要使用 HTTPS（Stripe 强制要求，其他服务商也建议使用）。
- 服务器的防火墙要允许支付平台的回调请求。
- 系统会自动验证签名，伪造的回调会被拒绝。
- 支付成功后，系统自动完成余额充值，不需要人工处理。

## 支付流程

```
用户选择充值金额和支付方式
       │
       ▼
  创建订单 (PENDING)
  ├─ 校验金额范围、待支付订单数、每日限额
  ├─ 负载均衡选择服务商实例
  └─ 调用服务商获取支付信息
       │
       ▼
  用户完成支付
  ├─ EasyPay    → 扫码 / H5 跳转
  ├─ 支付宝官方  → 桌面扫码单（当面付优先，电脑网站支付回退）/ 移动端 WAP 或当面付唤起 + 动态二维码备用页
  ├─ 微信官方    → 桌面 Native 扫码 / 非微信 H5 / 微信内 JSAPI
  ├─ Stripe     → Payment Element（银行卡/支付宝/微信等）
  └─ Airwallex  → 托管收银台
       │
       ▼
  支付回调验签 → 订单 PAID
       │
       ▼
  自动充值到用户余额 → 订单 COMPLETED
```

### 订单状态

| 状态 | 说明 |
| --- | --- |
| `PENDING` | 待支付，等待用户完成支付 |
| `PROCESSING` | 支付渠道报告处理中 |
| `PAID` | 已支付，等待充值到账 |
| `RECHARGING` | 正在发放权益 |
| `COMPLETED` | 已完成，余额已到账 |
| `EXPIRED` | 已过期，超时未支付 |
| `CANCELLED` | 已取消，用户主动取消 |
| `FAILED` | 充值失败，管理员可以重试 |
| `REFUND_REQUESTED` | 已申请退款 |
| `REFUNDING` | 退款处理中 |
| `REFUND_PENDING` | 渠道退款待确认 |
| `PARTIALLY_REFUNDED` | 部分退款 |
| `REFUNDED` | 已退款 |
| `REFUND_FAILED` | 退款失败 |

### 超时和补单

- 订单超时后，后台任务先查询上游的支付状态，再标记过期。
- 用户实际已经支付、只是回调延迟时，系统会通过查单补单。
- 后台任务每 60 秒检查一次超时。

## 核实未完成的退款

管理员订单页对 `REFUND_PENDING` 和 `REFUNDING` 状态的订单提供退款查单操作。渠道已经退款、但本地的成功记录写入失败时，先查单恢复，不要直接再退一次款。系统只在恢复资料有效时，才完成本地的状态和权益处理；渠道不支持查询、结果不明确或旧资料缺失时，按返回的提示人工核实。数据库里的退款准备和成功记录需要保留；降级到旧版本之前，先处理或登记未完成的退款。详见[退款](../../domains/payments_and_entitlements.md#退款)。

## 从 Sub2ApiPay 迁移

之前使用 [Sub2ApiPay](https://github.com/touwaeriol/sub2apipay) 作为外部支付系统的，可以迁移到内置支付。

### 主要差异

| 对比项 | Sub2ApiPay | 内置支付 |
| --- | --- | --- |
| 部署方式 | 独立服务（Next.js + PostgreSQL） | 内置在 TokenRouter 里，不需要另外部署 |
| 支付方式 | EasyPay、支付宝、微信、Stripe | EasyPay、支付宝、微信、Stripe、Airwallex |
| 配置方式 | 环境变量加独立的管理后台 | 在 TokenRouter 管理后台统一配置 |
| 充值对接 | 通过 Admin API 回调 | 内部直接处理，少一次跨服务调用 |
| 订阅套餐 | 支持 | 支持内置套餐和订阅权益 |
| 订单管理 | 独立的管理界面 | 集成在 TokenRouter 管理后台 |

### 迁移步骤

1. 在 TokenRouter 管理后台启用支付并配置服务商（使用相同的支付凭据）。
2. 把 Webhook 回调地址改成 TokenRouter 的回调地址。
3. 确认新订单能通过内置支付正常处理。
4. 停用 Sub2ApiPay 服务。

Sub2ApiPay 里的历史订单数据不会自动迁移。建议保留 Sub2ApiPay 一段时间，以便查询历史记录。
