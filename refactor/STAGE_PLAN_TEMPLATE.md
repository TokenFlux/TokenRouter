# 后端包重构阶段子计划模板

用于在计划模式中生成当前阶段的完整计划。参考结构填写实际内容后，将计划原样保存到 `refactor/Sxx-<主题>.md`；不要用未填写的模板宣布阶段计划已完成，也不提前创建全部阶段文件。

总计划：[BACKEND_PACKAGE_TARGET.md](BACKEND_PACKAGE_TARGET.md)。阶段文件持有详细决策与执行记录，总计划末尾 roadmap 只记录状态和有效子计划链接。

## 1. 阶段与基线

- 阶段编号、目标及本阶段范围：
- 计划日期、开始时 HEAD、已有工作区改动：
- 前置阶段及验收证据、尚存过渡依赖：
- 需要读取的 Project Doc 章节和现有契约测试：

## 2. 本阶段细化决策

逐项写出代码证据、候选方案、最终选择及其代价，覆盖实际涉及的内容：

- 模块/符号所有权，接口输入输出与具体调用方。
- 跨模块操作的事务所有者、参与方式、提交后副作用和失败语义。
- 认证、缓存、任务/流生命周期、装配和停止顺序。
- 新旧代码如何共存、共享状态如何保持唯一、依赖门禁例外及退出子步骤。
- 与总计划不同的结论、原因及需同步的总计划条目。

影响本阶段实施的问题必须明确决策；属于后续阶段的问题注明阶段、约束和已有适配方式。不得把尚待决策的前置条件当作已解决。

## 3. 包与符号迁移清单

| 旧包 / 文件 / 符号 | 目标所有者 / 路径 | 需要调整的调用方与测试 | 过渡方式 / 删除条件 |
| --- | --- | --- | --- |

## 4. 子步骤与交付顺序

按可独立验证的粒度列出子步骤；每步说明前置条件、具体变更、接入运行路径的方法、需要同步的 Wire/脚本/文档，以及完成标准。

## 5. 验证与回退

- 具体测试/构建/lint 命令、构建标签和关键测试名。
- 有关事务、并发、故障及兼容性的场景，所需 PostgreSQL/Redis/本地供应商夹具。
- 如何确认关键测试实际入选；环境不具备时的未验收项与补验条件。
- 混部、持久化兼容、回退单位和回退限制；不以代码回退代替数据库降级。
- 本阶段整体完成条件，以及可以交给下一阶段的接口和状态。

## 6. 执行记录（实施后仅在末尾追加）

保留已保存的计划正文；每次续做先读取最新执行记录。需要重新规划时，在计划模式形成独立的新版本，保留旧版并更新总计划 roadmap 的有效链接。

每条记录包含：

- 日期、子步骤、完成提交或等价变更证据。
- 实际迁移的包/符号、与计划的偏差及理由。
- 实际测试/构建/lint 命令、标签、关键测试入选和结果；未运行或未通过项。
- 剩余消费者、临时 Adapter、依赖例外及其退出条件；跨阶段事项链接至后续子计划或标明待创建阶段。
- Project Doc 与代码锚点的真实变更。
- 当前阶段状态、下一次可直接接续的动作；必要验收未通过时保持待验。

全部子步骤和必要验收通过后，记录阶段结论，并将总计划 roadmap 对应阶段标为已完成。
