# S10 后续职责与兼容入口

S10 已完成；验收与环境边界见 [acceptance.md](acceptance.md)，下一步编写 S11 子计划。

| 阶段 | 剩余职责 | S10 边界 |
| --- | --- | --- |
| S11 | 其余入站协议、工具识别/模拟输出、供应商错误捕获时机、全局重试与完成 worker | 已接入唯一 moderation/search；Grok/AlphaSearch 原生搜索仍在 upstream，不合并工具循环 |
| S12 | 支付、推广与退款业务触发 | 旧入口调用 notification 事件；投递失败不升级为权益回滚；资金/审计事务不变 |
| S13 | 创作与批量任务生命周期 | 沿用 NoMediaRetention、审核投影和原任务资金接口，不把通知或审核记录当作资金事实 |
| S14 | 安装、备份、升级和维护编排 | 不提前构造完整业务运行图；邮件/页面文件/搜索运行时按 app 生命周期关闭 |
| S15 | 设置聚合、旧 HTTP/DTO 汇总与窄来源投影 | site 的来源桥接只返回筛选后的公共值和认证/团队/用量投影；品牌、菜单、API/embed/CSP 实现在 site |
| S15/S16 | service/repository/pkg 兼容入口清零 | 唯一实现位于所属模块，旧入口只有别名、投影或委托；相关消费者由逐符号资料核对 |

- notification 的协调器与退订首次密钥保护限于单服务进程；未新增邮件 outbox 或 SMTP 恰好一次保证。
- search 的发布代次只在本进程内，Redis key/TTL、月度窗口及故障放行保持；取消回滚最多三秒，Redis 故障不能承诺退额成功。
- S04 平台额度协调和 S07 outbox 周期重建恢复限制保持，不扩大多实例支持。
- 阶段执行不新增历史问题审计。清单外偶然失败仅保留当次证据，阻塞验收时按计划请求调整。

## 固定修复回退风险

| 撤销项 | 恢复风险 |
| --- | --- |
| B01 | 同 delivery key 并发 SMTP 重复投递 |
| B02 | 首次退订密钥竞争，已签发令牌立即失效 |
| B03 | SMTP 取消无效、问候或读写等待脱离请求预算 |
| B04 | 已配置 Markdown 经符号链接读取页面根外文件 |
| B05 | 旧回源或 Manager 构建覆盖新配置发布 |
| B06 | 调用方修改 slice/指针污染运行配置 |
| B07 | 取消后已确认预占无法使用原请求 context 退额 |

按子步骤恢复代码、规则、装配和文档即可回退；数据库 schema、缓存协议和资金算法不变，不需要数据降级。保留其他任务与 S00—S09 冻结资料。
