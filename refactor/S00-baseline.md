# S00：冻结后端重构基线

## 1. 目标与当前状态

完成总计划 S00 的包清点、资金写入清单、依赖例外和验证基线，为 S01 提供可核对的输入。本阶段不移动运行代码，不调整公共 API、数据库、缓存或业务行为。

已核实：

- 当前分支为 `main`，HEAD 为 `1115294a9f69fcccd488c9a58006ebe875a32705`；实施开始时重新记录实际状态。
- 当前有 112 个 Go 目录、2666 个 Go 文件；54 个 Ent 目录和 58 个其他目录全部命中总计划映射。
- 工作区已有总计划搬迁、模板及其他任务文件的改动，保留其内容与暂存状态。
- 后端实际使用 Go 1.27.0；Docker 可用。本地 golangci-lint 2.12.2 因编译工具链低于 Go 1.27 而无法运行。
- pagination 普通测试已有缓存通过结果；尚未取得全量构建、测试和 lint 基线。

按用户确认，本阶段计划统一保存到 `refactor/S00-baseline.md`，不另存 `.agents/plans/`。

本地 lint 升级作为 S00 的准备步骤，采用 Homebrew 更新现有安装，替代此前的临时安装方案。

## 3. 实施顺序

1. **S00.0：保存计划与冻结快照。** 开始实施前原样保存本计划；文件存在后登记 roadmap 链接和“实施中”状态。记录实施时 HEAD、工作区及源文件摘要，后续新增内容按增量登记。随后更新本地 golangci-lint，记录更新前后版本并验证可用性。
2. **S00.1：完成所有权清点。** 对照总计划第 4、5 节逐项核对全部包及手写文件；补齐调用者、测试、Wire 和文档引用。每项必须有明确所有者和阶段，不能仅以文件名前缀推定混合职责。
3. **S00.2：展开资金与事务入口。** 覆盖总计划第 3.3 节全部十二组：普通结算、订阅与兑换、管理员调账、注册赠送、Key/成员/账号额度维护、平台额度、Promo Code、返利转余额、支付履约、退款、任务资金和初始化/恢复。追踪到实际写入方法与外层调用者，区分配置、消费累计和重置；通过事务取得、传递和提交代码确认原子范围。
4. **S00.3：形成 S01 依赖门禁输入。** 分类全部目标重合路径及待迁 `pkg`，逐文件列出依赖。重点核实 payment 的 Ent/config/Wire、websearch 的 Redis、xai 的 Redis/session 等现存耦合；同时记录现有 depguard 排除项。本阶段只登记，不修改 lint 规则。
5. **S00.4：运行验证并完成契约矩阵。** 将测试对应到资金原子性、金额精度、协议兼容、重试/取消、缓存一致性、运行模式和启停契约。复用已有测试；发现关键行为缺少覆盖时，先记录具体缺口，再补最小契约测试，保持运行代码与既有语义不变。
6. **S00.5：核对并交接。** 检查清单覆盖率、链接、测试结果及工作区差异，追加完成证据和后续阶段约束；总计划只更新 roadmap 状态、链接、完成数量与下一步。

## 4. 验证安排

**先更新本地 lint：**

- 执行 `brew upgrade golangci-lint`。当前 Homebrew 元数据提供 2.13.2，与 CI 的 v2.13 对齐；预演确认会同时将本地 Go 依赖从 1.26.2 更新到 1.27.1。
- 检查命令解析路径、`golangci-lint version` 和编译工具链版本，在后端目录运行 `golangci-lint run ./internal/pkg/pagination/...`，确认工具链兼容错误消失。
- 项目基线构建与测试显式使用 `GOTOOLCHAIN=go1.27.0`，与当前 CI 一致；记录系统 Go 与项目实际工具链的区别。

后端验证分别执行，保留独立结果；以下测试等价覆盖现有 Makefile 入口，不再重复全跑：

```bash
# backend 目录；仅对当前验证会话指定项目工具链
export GOTOOLCHAIN=go1.27.0

go test -count=1 -json ./...
go test -count=1 -json -tags=unit ./...
go test -count=1 -json -tags=integration ./...

golangci-lint run --timeout=30m ./...
golangci-lint run --timeout=30m --build-tags=unit ./...
golangci-lint run --timeout=30m --build-tags=integration ./...
```

- 普通构建使用 `make -C backend build`；通过 `make build-frontend` 生成真实前端产物后，执行 embed 构建，输出到未跟踪的构建目录。
- 使用 `go list` 核对各标签的测试文件选择；用实际测试事件确认关键测试执行。需要补查时使用对应标签的 `go test -list`，不将文件名包含 `integration` 当作构建标签。
- integration 使用现有 Testcontainers 的 PostgreSQL/Redis，记录实际镜像和测试执行情况。退出码为零但整体跳过、无匹配或仅完成编译，均不算行为验证通过。
- 重点验证资金幂等、金额量化、外层事务回滚、退款审计失败、任务预占释放，以及协议字段保留和真实输出后的重试边界。
- 记录 Darwin 专属文件与非 Darwin 实现的构建选择；增加 Linux 服务构建，跨平台编译只作为可构建性证据。
- 当前 E2E 未配置服务地址和测试密钥，且 Makefile 引用的 `e2e-test.sh` 不存在；登记为已有验证限制及 S16 跟踪项，不扩展本阶段去搭建真实供应商测试环境。
- 本阶段不改并发实现，不增加全量 race 或 benchmark；登记已有相关测试供所属迁移阶段使用。
- 收尾执行 `git diff --check`，核对运行代码、生成物和迁移 checksum 未发生意外变化。
